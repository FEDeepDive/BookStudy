## 📌실제 DOM

### 개념

- 웹페이지(문서)의 현재 상태를 실시간으로 표현한 것
- 브라우저가 문서를 인코딩하고 토큰화한 뒤, 의미 있는 `노드 객체`들로 **구조화**한 모델

### 문제점

- DOM 변경 시 리플로우/리페인팅 발생 → 크고 복잡한 앱에서 성능 저하 유발
    
    ```
    레이아웃 스래싱(Layout Thrashing)이란, 레이아웃 속성을 읽고 쓰는 작업이 자주 반복된 때 발생하는 불필요한 레이아웃 재계산을 의미한다. 레이아웃 스래싱은 성능을 저하시키고 사용자 경험을 악화한다.
    ```
    
- *브라우저 간 호환성 (브라우저마다 DOM 지원 기능, 이벤트 시스템이 달라 발생하는 문제)
- 페이지 복잡성이 증가할수록 API 조작과 관리가 어려움
- 변동 가능성이 높은 환경임

```
*리액트는 합성 이벤트 시스템(Synthetic Event System)으로 브라우저 간 이벤트 비일관성 문제를 해결한다. 합성 이벤트란 브라우저의 기본 이벤트를 감싼 wrapper 객체로, 브라우저마다 다른 이벤트 동작을 정규화한다.
```

## 📌문서 조각(DocumentFragment)

### 개념

- 가볍고 임시적인(=비활성화된, 메모리에 존재하는) 노드 객체 모델
- 문서 조각으로 변경 사항을 그룹화하고 실제 DOM에 적용해 성능을 최적화함

### 사용 방식

문서 조각에 노드를 추가해 원하는 구조 구성 → 해당 문서 조각을 DOM에 삽입

```jsx
const items = ['A', 'B', 'C', 'D'];

const fragment = new DocumentFragment(); // document.createDocumentFragment()와 같음
items.forEach((item) => {
	const li = document.createElement('li');
	li.textContent = item;
	fragment.appendChild(li); // 문서 조각에 노드 추가
});

document.getElementById('myList').appendChild(fragment); // 문서 조각을 DOM에 삽입
```

### 특징

- 여러 변경 사항을 **일괄 업데이트** (=리플로우/리페인팅 한 번만 발생)
- 문서 조각을 DOM에 삽입 시 문서 조각은 비워짐 ⇒ 메모리 사용량 최적화
- 문서 조각 변경이 실제 DOM에 영향 X (=성능 걱정 없이 조작 가능)
- DOM 삽입 전까지 문서 조각 내 노드에 스타일/스크립트 적용 X

## 📌가상 DOM 개념

- 실제 DOM의 가벼운 복사본
- 노드 객체로 이루어진 DOM과 달리, **일반적인 JS 객체로 구성** (ex. 리액트 엘리먼트)
- 여러 변경 사항을 **일괄 업데이트**해 실제 DOM 변경 횟수를 최소화함
- 디핑 작업과 재조정을 통해 트리 내 **변경된 부분만 업데이트**함

## 📌리액트의 가상 DOM 구현

### 리액트 엘리먼트

- 리액트 앱을 구성하는 가장 작은 블록
- 리액트 가상 DOM을 구성하는 JS 객체
- 속성
    
    ```jsx
    {
    	$$typeof: Symbol(react.element), // 엘리먼트의 종류 (element, portal, ...)
    	type: 'div', // 엘리먼트의 타입 (문자열이면 html 태그, 함수면 커스텀 컴포넌트)
    	key: null,
    	ref: null, // 참조하고 있는 DOM 노드
    	props: {}, // 전달받은 모든 속성과 프롭을 포함한 객체
    	_owner: null, // (내부 구현용) 이 엘리먼트의 업데이트를 담당할 컴포넌트
    	_store: {} // (내부 구현용) 엘리먼트의 상태/콘텍스트 정보 추적을 위한 객체
    }
    ```
    
    ```
    - 커스텀 컴포넌트 렌더링 방식: 리액트는 type이 함수인 엘리먼트를 만나면, 엘리먼트의 props를 전달하며 해당 함수를 호출함(=렌더링).
    - 호스트 컴포넌트 렌더링 방식: 리액트는 type이 문자열인 엘리먼트를 만나면, 설정된 문자열을 태그 이름으로 하는 HTML 엘리먼트를 생성하고 자식 노드를 렌더링함
    - 컴포넌트를 재귀적으로 호출하다 스칼라 값을 만나면 값을 텍스트 노드로 렌더링함.
    ```
    

### 재조정(Reconciliation)

리액트 컴포넌트의 상태/prop 변경 시 새 가상 DOM 생성 → 이전 가상 DOM과 비교(diffing) → 이전 트리를 새 트리와 일치하도록 만드는 데 필요한 최소 변경 횟수 계산

### 디핑(Diffing) 알고리즘

- 새 트리와 이전 트리를 비교해 변경 사항을 파악하기 위한 알고리즘
    - 알고리즘 상세
        
        ```
        - 두 트리의 루트 노드가 다른 경우, 기존 트리 전체를 새 트리로 대체
        - 루트 노드가 같다면, 노드의 속성이 변경된 경우에만 업데이트
        - 자식 노드가 다른 경우, 변경된 자식 노드만 업데이트 (하위 트리 전체를 생성하지 X)
        - 자식 노드 간 순서가 다른 경우, 순서를 다시 설정 (노드를 다시 생성하지 X)
        - 노드 추가/제거 시, 노드 추가/제거
        - 노드 타입 변경(ex. `div`→`span`) 시, 이전 노드 제거 후 변경된 타입의 새 노드 생성
        - key 프롭으로 노드의 교체가 필요한지 파악
        ```
        
- 디핑 알고리즘에 의해, **부모 노드 변경 시 변경되지 않은 자식 노드도 리렌더링되는 문제**

## 📌리액트 가상 DOM의 가치

(참고: p93, p99, p100, [가상DOM이 DOM보다 빠른가?](https://stackoverflow.com/questions/51435371/how-is-reacts-virtual-dom-faster-than-dom?utm_source=chatgpt.com), [가상DOM과 DOM 성능 비교](https://www.reddit.com/r/react/comments/1fb6f50/a_react_developers_dilemma_virtual_dom_vs_real/?utm_source=chatgpt.com&rdt=44064))

- 실제 DOM 조작을 최소화해 리플로우/리페인팅을 줄임
- 개발자가 UI와 로직에만 집중할 수 있도록 도움
    - 실제 DOM 추상화 & DOM API 사용 X
    - 합성 이벤트 시스템으로 브라우저 간 이벤트 비일관성 문제 해결(p101~102)
    - 일괄 처리, 재조정 등 몰라도 리액트 가상 DOM이 알아서 해줌
- 리액트 엘리먼트와 JSX를 제공해, UI를 간결하게 표현하고 쉽게 관리할 수 있게 함
- 로직을 컴포넌트화 할 수 있음
- DOM처럼 변동성이 큰 환경에서 상태 관리에 대한 걱정을 덜 수 있음

## 📌복습하기

- **❓DOM이란 무엇이며, 가상 DOM과 어떻게 다른가요?**
    
    DOM은 문서 객체 모델로 HTML 문서를 노드 객체로 구조화한 것입니다. 가상 DOM은 실제 DOM의 가벼운 복사본으로, JS 객체로 구성되어 있습니다. DOM은 변경 사항 하나하나가 리플로우/리페인팅을 발생시키는 반면, 가상 DOM은 변경 사항을 일괄적으로 업데이트하여 리플로우/리페인팅 횟수를 최소화합니다.
    
- **❓문서 조각이란 무엇이며, 리액트의 가상 DOM과 어떤 점에서 비슷하고 다른가요?**
    
    문서 조각은 임시적인 객체 모델입니다. DOM처럼 노드 객체로 이루어져 있지만, DOM과 달리 메모리에서만 임시적으로 사용됩니다. 문서 조각은 일괄 업데이트를 통해 리플로우/리페인팅 횟수를 줄인다는 점은 가상 DOM과 비슷하지만, 업데이트 방식에 차이가 있습니다. 문서 조각은 DOM에 직접 삽입되어 교체/추가하는 식으로 작동하고, 가상 DOM은 비교를 통해 변경된 부분을 파악해 DOM을 업데이트합니다.
    
- **❓DOM에서 문제가 되는 사안은 무엇인가요?**
    - 성능
        - DOM이 변경될 때마다 리플로우/리페인팅이 발생 (레이아웃 스래싱도 발생 가능)
        - 특정 노드를 탐색할 때 DOM의 전체 트리를 탐색해야 할 수 있음
    - 브라우저 간 호환성 유지 X
    - 페이지 복잡성이 증가할수록 DOM API 쓰기 복잡해짐
- **❓사용자 인터페이스를 더 빠르게 업데이트하는 데 가상 DOM이 어떻게 활용되나요?**
    
    💬아직도 DOM보다 가상 DOM이 빠르다고 할 수 있는지는 모르겠음
    
    DOM은 변경 사항을 업데이트하기 위해 DOM 전체 트리를 다시 렌더링하지만, 가상 DOM은 변경 사항이 있는 부분에 대해서만 업데이트를 수행합니다.
    
- **❓리액트의 렌더링은 어떻게 작동하나요? 이로 인해 잠재되었던 어떤 문제가 발생할 수 있나요?**
    
    💬리액트의 “리렌더링” 동작 방식과 이 방식에 의한 문제를 묻는 질문인 듯
    
    리액트는 최초에 렌더링을 하고, 상태 또는 프롭 변경 시 리렌더링이 트리거됩니다. 이 때 이전 가상 DOM과 현재 가상 DOM을 비교하는 디핑 작업을 수행하여 변경된 부분을 파악하는데, 디핑 알고리즘에 의해 부모 노드 변경 시 모든 자식 노드도 다시 렌더링되어야 하는 문제가 있습니다. `memo`, `useMemo` 등을 통해 이러한 문제를 해결할 수 있습니다.
    

## 💬느낀 점

- 레이아웃 스래싱 종종 들어봤는데 입에 잘 안 감긴다
- 가상 DOM이 생각보다 많은 일들을 하고 있군
- 가상 DOM이 빠르냐 물으면 긍정하진 못하겠지만, 실제 DOM의 어떤 점을 보완하기 위해 나왔으며 어떤 문제점이 있는지 잘 알게 됨
- 리액트가 리액트 엘리먼트를 렌더링하는 방식(type이 함수면 호출) 리액트 내부를 파보는 느낌이 들어서 흥미로웠음
- “리액트는 이벤트 리스너를 엘리먼트에 직접 추가하지 않고 루트에서 이벤트를 받는다” << 처음 알았다 리액트가 루트에 이벤트를 넣고 이벤트 위임+버블링으로 이벤트를 처리하고 있었다니;; 전혀 몰랐음
