## 3.1 가상 DOM 소개
- 가상 DOM은 HTML 문서를 자바스크립트 객체로 모델링한 것
  - DOM이든 가상 DOM이든 이 사실 자체는 동일!
  - DOM은 "노드 객체"로 구성되고 가상 DOM은 평범한 JS 객체로 구성된다는 큰 차이가 있음
    - 책에서는 이 이상 자세히 다루지 않지만, 더 자세히 파고들고 싶다면 [DOM 사양 문서](https://dom.spec.whatwg.org/)를 확인해도 좋을 듯
    - "노드 객체"란 [Node 인터페이스](https://dom.spec.whatwg.org/#node)를 구현하는 객체로, 단순한 JS 객체가 아님을 알 수 있다!
  - 리액트는 사용자의 UI 변경 지시가 있을 때마다 "재조정"이라는 과정을 거치며, 4장에서 좀 더 자세히 다뤄짐
  - 왜 why 굳이? 실제 DOM을 갱신하는 것이 다소 느리고 비용이 들기 때문!
    - 다만 이 부분은 살짝 논란이 있긴 합니다... [#](https://bohyunkang.tistory.com/170)
  - 브라우저가 문서의 레이아웃을 다시 계산하는 reflow(또는 relayout) 과정을 거치게 되면 성능에 영향을 주는데 가상 DOM은 해당 과정을 거치지 않음
  - 가상 DOM의 이전 버전과 새 버전을 비교하여 실제 갱신에 필요한 최소한의 변경 사항을 찾아 적용하기 때문에 성능 영향을 최소화

## 3.2 실제 DOM
- DOM은 웹 페이지의 현재 상태를 실시간으로 표현한 것이기 때문에, 사용자와의 상호작용에 의해 실시간으로 갱신됨
  - 이때 DOM은 문서의 일부분을 나타내는 노드의 트리 형태로 표현됨
  - 각 노드는 자바스크립트를 통해 조작할 수 있는 속성([property](https://github.com/FEDeepDive/FrontEnd/blob/hatchling13/1.%20HTML.md#6-html-%EC%9A%94%EC%86%8C%EC%9D%98-%EC%86%8D%EC%84%B1attribute%EA%B3%BC-%ED%94%84%EB%A1%9C%ED%8D%BC%ED%8B%B0property%EC%9D%98-%EC%B0%A8%EC%9D%B4%EC%A0%90))과 메서드를 포함
- 실제 DOM을 조작하는 것은 문제점이 많은 행동
  - 요소 추가/제거, 속성 확인/갱신 등의 작업은 겉으로는 간단해보여도 많은 비용이 발생할 수 있다!
  - 웹 페이지의 규모가 커지고 복잡해질수록 성능 문제는 커지며, 이를 완화하기 위한 여러 테크닉이 있지만 구현이 복잡할 수 있음
  - 이러한 실제 DOM의 복잡성을 추상화하기 위해 가상 DOM을 사용!
- 각 브라우저는 서로 다른 문서 모델링 방식을 가지고 있어 일관성이 보장되지 않기도 하는데 가상 DOM은 이를 완화할 수 있음
  - 리액트의 SyntheticEvent 객체는 브라우저의 기본 이벤트를 래핑하여 여러 브라우저 간의 일관성을 보장하기 위한 "통합 인터페이스"로써 설계됨
- 가상 DOM은 문서, 즉 DOM 트리의 일부분을 저장할 수 있는 [문서 조각](https://developer.mozilla.org/en-US/docs/Web/API/DocumentFragment) 개념을 더 나은 방식으로 구현한 것
  - 여러 번 개별적으로 업데이트하는 대신 모든 변경 사항을 일괄 처리(Batching)할 수 있어 [reflow 및 결정된 레이아웃에 따라 화면을 다시 그리는 repaint](https://github.com/FEDeepDive/FrontEnd/blob/hatchling13/9.%20WebBrowser.md#%EB%A6%AC%ED%8E%98%EC%9D%B8%ED%8C%85%EA%B3%BC-%EB%A6%AC%ED%94%8C%EB%A1%9C%EC%9A%B0%EC%9D%98-%EC%B0%A8%EC%9D%B4%EC%A0%90%EA%B3%BC-%EC%8B%A4%ED%96%89%EB%90%98%EB%8A%94-%EC%8B%9C%EC%A0%90) 과정이 한 번만 수행됨
## 3.3 가상 DOM 작동 방식
- 리액트는 사용자 인터페이스를 컴포넌트 또는 리액트 요소 트리로 표현
- 리액트 요소는 리액트 애플리케이션의 가장 작은 구성 단위
  - 해당 요소가 나타내야 하는 정보를 기술하는 평범한 자바스크립트 객체!
    - 이는 DOM 노드처럼 별다른 메소드 같은 게 없다는 의미로 이해할 수 있음
- 리액트 컴포넌트가 렌더링되면 리액트는 새로운 가상 DOM 트리를 생성하고 이전 가상 DOM 트리와 비교하여, 이전 트리를 새 트리와 일치하도록 갱신하는 데 필요한 최소 변경 횟수를 계산하는데 이 과정이 바로 "재조정 프로세스"!
  - 이때 두 트리를 비교하는 작업을 diffing이라 하고, 이 과정은 재귀적으로 이루어짐
  - (책에서 설명하는 별도의 알고리즘이 필요한 이유는 [구 버전의 리액트 문서](https://ko.legacy.reactjs.org/docs/reconciliation.html#motivation)에서 찾을 수 있습니다! 이렇게 보니 새로운 문서는 정말 많은 세부 사항을 숨기고 있네요)
  - 리액트의 diffing 알고리즘이 동작하는 근본적인 원리 때문에 발생하는 문제로 리렌더링이 존재함
    - 컴포넌트가 어느 상태에 종속되는지 알 수 없기 때문에 UI(와 상태)의 일관성을 위해 모든 컴포넌트를 날려버리고 다시 그리는 것!
    - 이러한 방식은 잠재적으로 성능 문제를 야기할 수 있기 때문에 주의깊은 최적화가 필요함

## 3.5 복습하기
1. DOM이란 무엇이며, 가상 DOM과 어떻게 다른가요?
  - DOM이란 HTML 문서를 자바스크립트 객체로 모델링했다는 점에서 가상 DOM과 같지만, DOM을 이루는 각 노드가 평범한 자바스크립트 객체가 아니라 특정한 인터페이스를 구현하여 추가적인 속성과 메소드를 가지는 객체라는 차이점이 있다!
2. 문서 조각이란 무엇이며, 리액트의 가상 DOM과 어떤 점에서 비슷하고 다른가요?
  - 문서 조각이란 DOM 트리의 일부분을 저장할 수 있으며, 실제 DOM에 영향을 주지 않으면서 여러 가지 갱신을 일괄적으로 수행할 수 있는 임시 저장소이다. 변경 사항을 일괄적으로 처리하기 때문에 reflow/repaint의 횟수를 줄일 수 있다는 점이 비슷하지만, 가상 DOM은 변경 사항을 효율적으로 반영하기 위해 필요한 계산 횟수를 계산할 수 있는 알고리즘을 적용할 수 있을 뿐만 아니라 여러 브라우저 간 동작의 일관성을 보장할 수 있다!
3. DOM에서 문제가 되는 사안은 무엇인가요?
  - 각 변경이 일어날 때마다 레이아웃을 다시 계산하고 그리는 데 드는 성능 문제, 여러 브라우저 간에 문서를 해석하여 나타내는 방식의 차이에서 발생하는 호환성 문제 등이 존재한다.
4. 사용자 인터페이스를 더 빠르게 업데이트하는 데 가상 DOM이 어떻게 활용되나요?
  - 실제 DOM 트리에 가해질 변경을 일괄적으로 적용하여 reflow/repaint가 발생하는 횟수를 줄이고, 이전 트리와 현재 트리 간 차이를 비교하여 변경을 최소화함으로써 실제 DOM을 더욱 빠르게 갱신하기 위해 활용될 수 있다.
5. 리액트의 렌더링은 어떻게 작동하나요? 이로 인해 잠재되었던 어떤 문제가 발생할 수 있나요?
  - 리액트는 컴포넌트 상태가 변경되면 해당 컴포넌트와 그 자손 컴포넌트를 재귀적으로 호출하며, 특정 컴포넌트가 어떤 상태에 종속되는지 알지 못하기 때문에 UI와 상태의 일관성을 위해 호출된 모든 컴포넌트를 다시 그리게 된다. 따라서 실제로 변경이 발생하지 않은 컴포넌트도 불필요하게 리렌더링하게 될 가능성이 있다.
