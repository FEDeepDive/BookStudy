## 1. JSX란 무엇이며 장단점은 무엇인가요 ?

### `보경`

- JSX는 JS의 확장 구문으로 HTML과 JS가 혼합된 로직을 쉽게 사용할 수 있다는 장점이 있다.
- 책에서는 러닝커브가 있으며 컴파일러가 필요하다가 단점이라는데 난 모르겠다.

### `미림`

- JSX 개념
  - 자바스크립트 확장 구문 (Javascript Syntax eXtension)
  - 자바스크립트 코드 내에서 HTML과 유사한 마크업 코드 작성 O
- 장점
  - 엘리먼트 트리 내부에서 표현식 사용 가능 ⇒ 유연함
  - 타입 안정성 향상이 가능 (ex. TypeScript, JSDoc, [propTypes](https://ko.legacy.reactjs.org/docs/typechecking-with-proptypes.html))
- 단점
  - 관심사 분리 X (표현-논리 혼합)
  - JSX를 JS로 변환하기 위한 전용 도구가 필요

### `정욱`

- 자바스크립트 코드 안"에서, "HTML과 유사한 코드"를, 작성할 수 있게 해주는 "구문 확장 문법"
- 자바스크립트로 코드를 쓰면서 선언적으로 UI를 선언할 수 있다는 장점이 있음
- 개인적으로는 저 위의 모든 단점에 동의하지 않음... 진짜 HTML을 작성하는 것이 아님에도 HTML을 작성하는 것처럼 느껴져서 혼동이 올? 수도? 있겠다 정도?

### `영은`

별도의 언어가 아니라 자바스크립트에서 XML문법을 확장한 구문확장자

- 장점: html이 익숙한 개발자에게 가독성 좋고 타이핑이 쉽다.
- 실제로는 **Babel** 등이 JSX를 JS 객체 트리로 변환
  - blog.jsx
    ```jsx
    const author = 'Jae Doe';
    const postContent = await readFile('./posts/hello-world.txt', 'utf8');

    const jsxElement = (
      <html>
        <head>
          <title>My blog</title>
        </head>
        <body>
          <nav>
            <a href='/'>Home</a>
            <hr />
          </nav>
          <article>{postContent}</article>
          <footer>
            <hr />
            <p>
              <i>
                (c) {author}, {new Date().getFullYear()}
              </i>
            </p>
          </footer>
        </body>
      </html>
    );
    ```
  - js tree 로 변환
    ```jsx
    {
      $$typeof: Symbol.for("react.element"), // 리액트에게 JSX라고 보내는 신호 (예. <html>)
      type: 'html',
      props: {
        children: [
          {
            $$typeof: Symbol.for("react.element"),
            type: 'head',
            props: {
              children: {
                $$typeof: Symbol.for("react.element"),
                type: 'title',
                props: { children: BlogPost }
              }
            }
          },
          {
            $$typeof: Symbol.for("react.element"),
            type: 'body',
            isServer: false,
            props: {
              children: [
                {
                  $$typeof: Symbol.for("react.element"),
                  type: 'nav',
                  props: {
                    children: [{
                      $$typeof: Symbol.for("react.element"),
                      type: 'a',
                      props: { href: '/', children: 'Home' }
                    }, {
                      $$typeof: Symbol.for("react.element"),
                      type: 'hr',
                      props: null
                    }]
                  }
                },
                {
                  $$typeof: Symbol.for("react.element"),
                  type: 'article',
                  props: {
                    children: postContent
                  }
                },
                {
                  $$typeof: Symbol.for("react.element"),
                  type: 'footer',
                  props: {
                    /* ...계속... */
                  }
                }
              ]
            }
          }
        ]
      }
    }
    ```
- `{}` 안에서 JS 표현식 사용 가능, 문자열 보간보다는 더 안전하고 문법 체크가 엄격.
- JSX 내부에서는 항상 값을 리턴해야 함으로 if문이나 switch같은 블록은 지원하지 않음
  → JSX 내부에서는 삼항 연산자(`condition ? A : B`)를 사용할 수 있지만, 블록문(`if {}`)을 사용할 수 없다

## 2. JSX와 HTML의 차이점은 무엇인가요 ?

### `보경`

- HTML은 마크업 언어로 웹페이지가 어떻게 이루어져 있는지를 표현하는 문서
- JSX는 자바스크립트 확장 구문으로 HTML과 유사하게 생겼지만 컴파일이라는 과정을 통해 JS로 변환되어 HTML에 적용된다.

### `미림`

|                 | JSX                               | HTML                                 |
| --------------- | --------------------------------- | ------------------------------------ |
| 개념            | JS의 확장 구문                    | 마크업 언어                          |
| 인라인 표현식   | O                                 | X                                    |
| 속성 네이밍     | 카멜 케이스 (ex. onClick)         | 소문자만 사용 (ex. onclick, data-\*) |
| 엘리먼트 네이밍 | 파스칼 케이스 (ex. Div)           | 소문자만 사용 (ex. div)              |
| 💬태그 규칙     | 단일 요소로 반환 & 모든 태그 닫기 | -                                    |

### `정욱`

- 중괄호를 사용해 자바스크립트 표현식을 삽입할 수 있어 동적인 UI를 작성하기 쉬우며, 속성 작성 시 네이밍 컨벤션이 `camelCase`라는 차이점이 있음
- 추가로, 어쨌든 자바스크립트 코드이기 때문에 특정 자바스크립트 예약어를 사용할 수 없다! `class`를 사용할 수 없어서 `className`을 쓴다던가 `for`를 못 써서 `htmlFor`을 쓴다던가

### `영은`

1. 중괄호를 사용해 js표현식을 사용가능
2. JSX에서는 속성을 `onClick`처럼 camelCase로 작성해야 합니다.
3. html은 브라우저에서 사용 jsx는 js에서 사용

## 3. 텍스트 문자열은 어떻게 기계어가 되나요 ?

### `보경`

- 토큰화 : 문자열을 이해할 수 있는 최소 단위인 토큰으로 분해함
- 구문 분석 : 토큰들이 추상구문트리로 변환됨
- 코드 생성 : 추상구문트리를 실행할 수 있는 기계어로 변환함
  - 좀 더 정확히는 Ignition 인터프리터를 통해 바이트 코드(중간코드)로 변환하여 한 줄씩 실행하고, TuroboFan 컴파일러를 통해 중간코드를 기계어로 변환하여 최적화한다.

### `미림`

`컴파일` 과정을 통해 문자열 뿐인 소스 코드를 컴퓨터가 이해할 수 있는 기계어로 변환한다.

컴파일 과정은 크게 1️⃣`토큰화`, 2️⃣`구문 분석(Parsing)`, 3️⃣`코드 생성`으로 이루어진다.

1️⃣먼저 문자열을 의미가 있는 ‘토큰’으로 분해한다. 정규 표현식을 사용해 문자열을 규칙에 따라 토큰으로 분해할 수 있다.

2️⃣이후 토큰을 가지고 구문 트리(Syntax Tree)를 생성한다. 구문 트리는 코드의 구조를 나타내는 자료 구조이다.

3️⃣추상 구문 트리(AST)를 컴퓨터가 이해할 수 있는 기계어로 변환하고 실행한다.

### `정욱`

문자열을 의미있는 단위로 나누는 토큰화(tokenization) 과정, 토큰을 가져와 추상 구문 트리(abstract syntax tree, AST)로 변환하는 파싱(parsing) 과정, AST를 기계어로 변환하는 코드 생성(code generation, codegen) 과정을 거쳐 텍스트 문자열 형식의 소스 코드가 실행될 수 있는 기계어로 변환됨

### `영은`

1. **토큰화 (Tokenization, Lexical Analysis)** → 코드를 작은 토큰으로 분해
2. **구문 분석 (Parsing)** → 토큰을 AST(추상 구문 트리)로 변환
3. **(옵션) 트랜스파일링 (Transpiling)** → Babel, TypeScript 변환 과정
4. **바이트코드 생성** → AST를 바이트코드로 변환
5. **인터프리터 & JIT 컴파일러 실행** → JIT이 핫 코드를 기계어로 변환하여 최적화

## 4. JSX 표현식이란 무엇이며 어떤 좋은점이 있나요?

### `보경`

- JSX 내부에서 JS 코드를 쓸 수 있게 해줘서 HTML을 동적으로 수정할 수 있도록 한다.

### `미림`

- 자바스크립트 표현식을 중괄호로 감싸서 엘리먼트 트리 안에서 사용 가능
- ⇒ 삼항 연산자로 조건 검사, JS 메서드 사용 등 **생산성 ↑, 유연함 ↑**

### `정욱`

- JSX 코드 작성 시 요소 트리 내에서 중괄호 안에 작성할 수 있는 자바스크립트 표현식
- 목록 반복을 통해 복수 개의 요소 생성, 삼항 연산자를 이용해 조건부 렌더링, 데이터 조작 후 렌더링 등이 가능함

### `영은`

> **얼마전에 본 강의자료**

JSX(React 엘리먼트) 종류:

> 1. **문자열 / 숫자** → 그대로 HTML 텍스트
> 2. **배열** → 순회하며 각각 렌더
> 3. **태그(String type)** → `<div>...</div>`처럼 HTML 태그로 변환
>
>    - renderJSXToHTML 1버전
>      ```jsx
>      function renderJSXToHTML(jsx) {
>        if (typeof jsx === 'string' || typeof jsx === 'number') {
>          // This is a string. Escape it and put it into HTML directly.
>          return escapeHtml(jsx);
>        } else if (jsx == null || typeof jsx === 'boolean') {
>          // This is an empty node. Don't emit anything in HTML for it.
>          return '';
>        } else if (Array.isArray(jsx)) {
>          // This is an array of nodes. Render each into HTML and concatenate.
>          return jsx.map((child) => renderJSXToHTML(child)).join('');
>        } else if (typeof jsx === 'object') {
>          // Check if this object is a React JSX element (e.g. <div />).
>          if (jsx.$$typeof === Symbol.for('react.element')) {
>            // Turn it into an an HTML tag.
>            let html = '<' + jsx.type;
>            for (const propName in jsx.props) {
>              if (jsx.props.hasOwnProperty(propName) && propName !== 'children') {
>                html += ' ';
>                html += propName;
>                html += '=';
>                html += escapeHtml(jsx.props[propName]);
>              }
>            }
>            html += '>';
>            html += renderJSXToHTML(jsx.props.children);
>            html += '</' + jsx.type + '>';
>            return html;
>          } else throw new Error('Cannot render an object.');
>        } else throw new Error('Not implemented.');
>      }
>      ```
>
>    ### 컴포넌트 개념
>
>    - “**재사용 UI 묶음** + **props**로 데이터 전달” → React에서 가장 핵심적인 개념
>    - 위 코드를 컴포넌트로 분리하기
>      ```jsx
>      function Footer({ author }) {
>        return (
>          <footer>
>            <hr />
>            <p>
>              <i>
>                (c) {author}, {new Date().getFullYear()}
>              </i>
>            </p>
>          </footer>
>        );
>      }
>
>      function BlogPostPage({ postContent, author }) {
>        return (
>          <html>
>            <head>
>              <title>My blog</title>
>            </head>
>            <body>
>              <nav>
>                <a href='/'>Home</a>
>                <hr />
>              </nav>
>              <article>{postContent}</article>
>              <Footer author={author} />
>            </body>
>          </html>
>        );
>      }
>      ```
>    - 컴포넌트로 분리된 코드 호출
>      ```jsx
>      createServer(async (req, res) => {
>        const author = 'Jae Doe';
>        const postContent = await readFile('./posts/hello-world.txt', 'utf8');
>        sendHTML(res, <BlogPostPage postContent={postContent} author={author} />);
>      }).listen(8080);
>      ```
>
>    컴포넌트가 함수여서 생기는 문제 (function이란 태그가 html에서 부자연스러움)
>
>    ```
>    <!-- This doesn't look like valid at HTML at all... -->
>    <function BlogPostPage({postContent,author}) {...}>
>    </function BlogPostPage({postContent,author}) {...}>
>    ```
>
>    - renderJSXToHTML 2버전
>      이 코드를 추가함
>      ```jsx
>      if (jsx.$$typeof === Symbol.for('react.element')) {
>        if (typeof jsx.type === 'string') {
>          // Is this a tag like <div>?
>          // Existing code that handles HTML tags (like <p>).
>          let html = '<' + jsx.type;
>          // ...
>          html += '</' + jsx.type + '>';
>          return html;
>        } else if (typeof jsx.type === 'function') {
>          // Is it a component like <BlogPostPage>?
>          // Call the component with its props, and turn its returned JSX into HTML.
>          const Component = jsx.type;
>          const props = jsx.props;
>          const returnedJsx = Component(props);
>          return renderJSXToHTML(returnedJsx);
>        } else throw new Error('Not implemented.');
>      }
>      ```
>      ```jsx
>      function renderJSXToHTML(jsx) {
>        if (typeof jsx === 'string' || typeof jsx === 'number') {
>          return escapeHtml(jsx);
>        } else if (jsx == null || typeof jsx === 'boolean') {
>          return '';
>        } else if (Array.isArray(jsx)) {
>          return jsx.map((child) => renderJSXToHTML(child)).join('');
>        } else if (typeof jsx === 'object' && jsx.$$typeof === Symbol.for('react.element')) {
>          // Element(React 엘리먼트)
>          if (typeof jsx.type === 'string') {
>            // html 태그(<div>, <span> 등)
>            let html = `<${jsx.type}`;
>            const props = jsx.props || {};
>            for (const propName in props) {
>              if (propName !== 'children') {
>                html += ` ${propName}="${escapeHtml(props[propName])}"`;
>              }
>            }
>            html += '>';
>            html += renderJSXToHTML(props.children);
>            html += `</${jsx.type}>`;
>            return html;
>          } else if (typeof jsx.type === 'function') {
>            // 컴포넌트
>            const Component = jsx.type;
>            const props = jsx.props || {};
>            const renderedJSX = Component(props);
>            return renderJSXToHTML(renderedJSX);
>          }
>          // 확장 가능...
>        }
>        // ...
>      }
>      ```
>    - `renderJSXToHTML(<BlogPostPage postContent="..." author="..." />)` 호출 시 → `<BlogPostPage>` 컴포넌트 내부 JSX가 HTML이 됨
