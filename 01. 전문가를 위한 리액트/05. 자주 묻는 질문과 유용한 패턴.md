## 5.1 React.memo를 사용한 메모화
- 메모화란 전산학에서 이전에 계산된 결과를 캐싱해서 함수의 성능을 최적화하는 기법
  - 계산 비용이 많이 들거나 자주 호출되는 함수를 실행하는데 필요한 자원을 줄일 수 있음
  - 순수 함수여야 함
  - (#) 메모화는 보통 알고리즘 문제 풀 때 많이 듣던 개념!!!
- 리액트에서는 `React.memo`를 사용해 함수 컴포넌트에 메모화를 적용할 수 있음
  - `React.memo`로 감싸진 함수는 props가 변경되지 않는 한 재조정 과정에서 다시 호출되지 않음
    - 이는 곧 불필요한 렌더링을 방지해서 성능이 전반적으로 향상된다는 뜻
- 그래서 얼마나 자주, 많이 메모화해야 할까?
  - `React.memo`는 props에 "얕은 비교"를 수행해 변경 여부를 확인!
  - 그러나 스칼라(원시) 타입이 아닌 참조 타입은 정확하게 비교하기 힘듦ㅠㅠ
  - 참조 타입은 데이터 자체가 아니라 데이터가 메모리에 저장된 위치에 대한 참조를 저장함
    - 보통 객체나 배열 타입을 생각하지만 자바스크립트에서는 함수도 참조 타입!
  - 내용이 같아도 메모리 위치가 다른 두 개체는 `===`(엄격한 동등성 연산자)를 사용해 비교할 때 서로 같지 않은 것으로 간주됨
    - 예를 들어 배열을 props로 받는 컴포넌트의 경우 `React.memo`로 감쌌다고 하더라도 props로 전달되는 배열이 매번 새로 만들어지기 때문에 불필요한 렌더링이 발생함
      - 이런 경우 `useMemo` 훅으로 배열을 메모화해야 문제가 해결됨
    - 함수를 props에 넘겨주는 경우에도 비슷한 상황이 발생함
      - 함수의 경우 `useCallback` 훅으로 문제를 해결할 수 있음
  - `React.memo`는 컴포넌트를 절대 리렌더링하지 않게 만드는 장치가 아니라, 재조정자에게 전달하는 힌트!
    - 이를 통해 사용자가 원하는 UI를 렌더링하는 최선의 방법을 찾아내는 것은 여전히 리액트의 몫
    - 리액트는 메모화된 컴포넌트를 만났을 때 갱신이 필요한지 건너뛸 수 있는지 판단하는 함수가 구현되어있음
      - 상태나 컨텍스트 변경에 의해 예정된 갱신이 없고, 기존 props와 새 props를 비교한 결과 둘이 서로 같다면 재렌더링되지 않음
      - props 비교에는 사용자가 직접 비교 함수를 제공할 수도 있음

## 5.2 useMemo(# useCallback)를 사용한 메모화
- 전체 컴포넌트를 메모화하여 "재렌더링을 줄이는" `React.memo`와 달리 `useMemo`는 컴포넌트 내부의 특정 계산을 메모화하여 비싼 계산을 다시 하지 않고 결과에 대한 일관된 참조를 유지함
- **그러나 useMemo를 모든 곳에 적용한다고 해서 성능에 득이 되지는 않음**
  - 스칼라 값은 자바스크립트에서 참조가 아닌 실젯값으로 전달되고 비교되기 떄문에 `useMemo`를 사용하는 것이 더 비싼 작업이 될 수 있음
  - 또한 내장 컴포넌트 또는 호스트 컴포넌트에 전달되는 몇몇 props는 사용자 정의 컴포넌트와는 다르게 취급됨
    - 이벤트 기반 props의 경우 리액트는 내부적으로 이벤트 핸들러를 DOM에 직접 추가하지 않고 **이벤트 위임**을 사용해 최적화함!
    - 내장 컴포넌트는 리렌더링된 상위 컴포넌트의 일부가 아닌 경우 함수 props가 변경되었다고 해서 리렌더링되지 않음
    - 리액트는 내장 컴포넌트에서 변경 사항 감지를 위해 함수에 대해 깊은 비교를 수행하지 않기 때문에 성능이 절약됨
  - 내장 컴포넌트를 사용할 때는 신경을 좀 덜 써도 된다는 뜻!
- `useCallback`은 자주 리렌더링할 가능성이 있는 컴포넌트가 있고, `React.memo` 등으로 최적화된 하위 컴포넌트에 콜백을 전달할 때 매우 유용함
  - (#) `useEffect`를 사용할 때도 많이 쓰이더라구요
  - `useCallback`은 본질적으로 함수를 위한 `useMemo`!
- (#) 진리의 케바케... 측정하지 않으면 개선할 수 없다
- 이 모든 것을 최적화해줄 [리액트 컴파일러](https://ko.react.dev/learn/react-compiler)...는 언제 사용할 수 있을지
