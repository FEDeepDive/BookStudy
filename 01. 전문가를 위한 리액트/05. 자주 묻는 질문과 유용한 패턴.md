## 📌리액트의 메모화

### 리액트의 리렌더링 조건 (p112 Recap)

리액트는 컴포넌트의 상태/프롭이 변경되면 업데이트를 반영하기 위한 새로운 리액트 엘리먼트 트리를 생성한다. 리액트는 디핑 알고리즘을 통해 새 트리 전체가 아닌, 이전 트리에서 변경된 부분만 리렌더링한다.

그러나 **“불필요한 리렌더링”이 야기**되는 경우가 있는데, 바로 부모 노드가 변경되었을 때이다. 디핑 알고리즘에는 ‘부모 노드 변경 시 하위 트리 전체를 새 트리로 대체한다’라는 규칙이 있는데, 이 때문에 하위 트리 전체가 리렌더링되는 문제가 발생한다.

이러한 문제를 해결하기 위해 리액트는 메모화를 통한 최적화 방식을 제공해 왔다. 리액트 컴파일러가 메모화를 자동화

### `memo()`

상위 컴포넌트가 리렌더링되더라도 `memo`로 감싼 컴포넌트는 프롭이 바뀌지 않으면 재호출되지 않는다(대신 기존 파이버를 재사용함. =bailout). 즉 `memo`는 컴포넌트의 **프롭이 변경되었을 때만 리렌더링**하게 한다. (단, 사용중인 Context가 변경되면 메모 컴포넌트도 리렌더링된다)

- **레퍼런스**
    - 매개변수: 메모할 컴포넌트, (optional) 프롭 비교 함수 (기본값: `Object.is`)
    - 반환 값: 메모한 컴포넌트
        - ⇒ 기존 컴포넌트와 동일하게 동작하지만, 프롭 변경이 없으면 리렌더링되지 않음

프롭 비교는 얕은 비교로 수행된다. 만약 프롭이 스칼라 타입이면 값 자체를 비교하지만, **참조 타입이면** 참조 값을 비교하기 때문에 **실제 내용이 동일하더라도 비교 결과는 동등하지 않은 것으로 간주**된다. 즉 컴포넌트를 `memo`로 감싸도, **프롭이 참조 타입(ex. 객체, 배열, 함수 등)이면 매번 리렌더링된다.**

```jsx
const Profile = memo(function Profile({ person }) {
  // ...
});

function Page() {
	const [like, setLike] = useState(false);
  const person = { name: 'Kim', age: 18 }; // 매 렌더링마다 새로운 객체가 생성됨
  
  return (
	  <>
		  <button onClick={() => setLike(!like)}>좋아요</button>
		  <Profile person={person} /> {/* memo했지만 매번 리렌더링 됨 */}
	  </>
  );
}
```

이러한 문제를 해결하기 위해 `useMemo`, `useCallback`를 사용할 수 있다.

### `useMemo()`

인자로 받은 **함수의 반환값을 메모**한다. `useMemo`를 사용하면 컴포넌트가 리렌더링되더라도 값을 새로 생성하지 않고, **종속성이 변경될 때만 함수를 다시 실행해 새로운 값을 메모**한다. `useMemo`를 통해 1️⃣비용이 비싼 연산(ex. 정렬, 필터, 매핑 등)의 횟수를 줄이거나, 2️⃣`memo`한 컴포넌트의 프롭으로 전달되는 참조를 메모해 해당 컴포넌트의 리렌더링을 건너뛸 수 있다.

- **레퍼런스**
    - 매개변수: 계산 함수, 종속성 배열
    - 반환 값: 계산 함수의 반환 값
        - ⇒ 종속성이 변경될 때에만 값을 다시 메모함
- **예제**
    
    ```jsx
    const Profile = memo(function Profile({ person }) {
      // ...
    });
    
    function Page({ people }) {
    	const [like, setLike] = useState(false);
    	
    	// ✅ useMemo()로 이득을 보는 경우
    	// 1. 계산 함수의 연산 비용이 비싼 경우
    	const friends = useMemo(() => people.filter((p) => isFriend(p), [people]);
    	
    	// 2. 메모한 값을 프롭으로 받는 컴포넌트의 렌더링 비용이 큰 경우
      const person = useMemo(() => ({ name: 'Kim', age: 18 }), []);
      
      return (
    	  <>
    		  <button onClick={() => setLike(!like)}>좋아요</button>
    			<Profile person={person} />
    			<ul>
    				{friends.map((friend) => (
    					<li key={friend.id}>{friend.name, friend.age}</li>
    				))}
    			</ul>
    	  </>
      );
    }
    ```
    

### `useCallback()`

인자로 받은 **함수 정의를 메모**한다. `useCallback`을 사용하면 컴포넌트가 리렌더링되더라도 함수를 새로 생성하지 않고, **종속성이 변경되었을 때만 새로운 함수 정의를 메모**한다. `useCallback`을 통해 1️⃣하위 컴포넌트에 전달할 함수를 메모해 함수 생성을 매번 하는 것을 방지할 수 있고, `memo` 컴포넌트에 프롭으로 전달할 함수를 메모해 리렌더링을 건너뛸 수 있다.

내장 컴포넌트 또는 호스트 컴포넌트의 함수 프롭을 `useCallback`으로 메모이제이션하면 부하만 더하고 별로 도움이 되지 않으니 하지 말자.

## 📌지연 로딩(Lazy Loading)과 서스펜스(Suspense)

- 문제: 자바스크립트 번들 다운로드로 인해 페이지 로딩이 느려지거나 데이터 사용량이 증가
    - ⇒ 코드 분할(Code Splitting): 특정 페이지나 기능에 필요한 스크립트만 읽어 들임
    - ⇒ 지연 로딩(Lazy Loading): 초기 실행에 필수적이지 않은 스크립트의 로딩을 미룸
- 리액트에서 해결 방법: 지연 로딩과 서스펜스 사용
    - **지연 로딩(Lazy Loading)**
        - 초기 로딩에 필수적이지 않은 자바스크립트 로딩을 지연해 페이지 로드 시간과 데이터 사용량을 줄이는 최적화 기법
        - 예를 들어 버튼을 눌렀을 때 사이드바가 나타나는 UI에서, 사이드바 크기가 큰 경우 지연 로딩을 적용하여 사이드바를 펼치기 전까지 스크립트를 로드하지 않도록 할 수 있음
    - **서스펜스(Suspense)**
        - 프로미스가 해결되기 전까지 폴백(fallback) UI를 제공
    - **지연 로딩 + 서스펜스**
        - 서스펜스로 지연 로드하는(=비동기로 읽어들이는) 요소를 감싸 인터페이스 응답성을 높임

## 📌리액트의 상태 관리 훅

- `useState()`
    - 단일 상태 관리에 사용
- `useReducer()`
    - 복잡한 상태(ex. 객체) 관리에 사용
    - 장점
        - 상태 업데이트 로직(`reducer` 함수)을 컴포넌트와 분리 가능 ⇒ 테스트성, 재사용성 증가
        - 이벤트 소스 모델로, 앱 내 이벤트를 재생해 진단 로그를 추적하는 데 사용 가능(ex. 버그 재연, 시간 여행 디버깅)
    - 단점
        - 코드가 장황해짐
- Immer
    - 리액트 라이브러리로 복잡한 상태(ex. 중첩 객체) 관리 처리에 유용
    - 기존 리듀서에서는 중첩된 객체 속성을 편집할 때 전개나 `Object.assign`으로 해야 했지만, `useImmerReducer`를 사용하면 값을 객체 속성에 직접 할당하여 상태 업데이트를 할 수 있음
    - `useState`와 함께 사용해 현재 상태 기반의 불변성을 보장하면서 다음 상태를 생성할 수 있음
