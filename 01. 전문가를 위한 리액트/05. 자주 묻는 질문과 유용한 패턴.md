## 1. 리액트에서 메모화란 무엇이며, 컴포넌트 렌더링을 최적화하는 데 어떻게 사용할 수 있을까요?

### `보경`

- 메모화 : 이전에 그려진 컴포넌트를 캐싱해 렌더링을 최적화하는 방법
- 이전에 그려진 컴포넌트가 순수함수이고, props가 바뀌지 않아 리렌더링을 할 필요가 없을 때 React.memo를 사용해 컴포넌트를 캐싱할 수 있다.


### `미림`

프로그래밍에서 ‘메모화’란 함수의 결과 값을 메모하여, 동일한 함수를 다시 실행해야 할 때 메모한 값을 재사용하는 최적화 기법입니다. 리액트는 **디핑 알고리즘에 의한 불필요한 리렌더링 문제를 방지하는 방안으로 컴포넌트나 함수, 프롭 등을 메모화하는 방법을 제공**합니다.

리액트는 컴포넌트 렌더링을 최적화하기 위해 `React.memo`로 컴포넌트를 메모화해 프롭 변경 시에만 리렌더링합니다. 이때 컴포넌트가 객체를 프롭으로 갖는다면, 프롭이 변경되지 않아도 변경된 것으로 간주될 수 있습니다. 이를 방지하기 위해 `useMemo`로 프롭을 메모화합니다.

`useMemo`는 비용이 비싼 함수의 결과 값을 메모화하는 데에도 사용할 수 있고, `useCallback`를 사용하면 함수 정의 자체를 메모화할 수 있습니다.

### `정욱`

- 리액트에서 메모화란 컴포넌트를 DOM에 배치하거나 갱신하는 과정에서 복잡한 계산이 많은 경우, 렌더링이 오래 걸리는 문제를 방지하기 위해 비용이 큰 계산의 결과를 캐싱(저장)해두는 것
- 이렇게 캐싱된 값을 이용하여 실제로 변경된 컴포넌트만 다시 렌더링하고 변경되지 않은 컴포넌트는 캐싱된 결과를 보여주어 불필요한 리렌더링을 줄일 수 있음

### `영은`

메모화는 동일한 입력값에 대해 이전 결과를 재사용하여 불필요한 계산과 렌더링을 방지하는 기법으로, React.memo, useMemo, useCallback을 통해 컴포넌트나 값, 함수를 메모화해 성능 최적화를 유도한다.


## 2. 리액트에서 상태 관리를 위해 useReducer를 사용하면 어떤 우세한 점이 있으며, useReducer는 useState와 어떻게 다른가요?

### `보경`

- useState는 useReducer를 추상화 한 함수로 단일 값을 관리하는데 용이하고 useReducer는 복잡한 객체 상태를 관리하는데 용이하다.
- useReducer 를 사용할 경우 우세한 점
    1. 상태 업데이트 로직을 분리해 단일책임원칙을 지킬 수 있으며, 테스트 코드 작성하기 쉽다.
    2. useReducer 액션 함수를 통해 상태 변화의 흐름을 명시적으로 확인할 수 있다.
    3. useReducer는 이벤트 소스 모델을 사용하기 때문에 이벤트의 진단 로그를 딸 수 있다. << 그냥 개발자에겐 도움되진 않지만, 라이브러리 개발자에겐 유용할 듯

### `미림`

useState와 useReducer 모두 상태 관리를 위한 훅이지만, useState는 단일 상태 관리에, useReducer는 객체처럼 복잡한 상태 관리에 강점을 보입니다. 또 useReducer를 사용하면 리듀서 함수를 작성해야 하는데, 이를 통해 다양한 케이스(action)에 대한 상태 업데이트 로직을 한 곳에서 관리할 수 있게 됩니다. 뿐만 아니라 리듀서 함수를 컴포넌트와 분리할 수 있어 따로 테스트하기 용이하거나 다른 컴포넌트에서 재사용할 수 있다는 이점이 있습니다.

### `정욱`

- useReducer를 사용하면 상태 갱신 로직을 컴포넌트에서 분리해 단독으로 테스트하거나 다른 컴포넌트에서 재사용이 가능해짐
- 또한 useReducer는 이벤트 소싱 패턴을 따르기 때문에 데이터 변경의 원인을 쉽게 추적할 수 있다는 장점도 존재
- useReducer는 useState의 하위 추상화로 볼 수 있으며, 상태 기반인 useState와 달리 useReducer는 이벤트 기반 아키텍처를 따르기 때문에 복잡한 상태 변경 로직이 필요한 경우 사용하기 좋음

### `영은`

useReducer는 복잡한 상태 변경 로직을 명확하게 분리할 수 있어 상태 전이 흐름을 예측 가능하게 만들며, 여러 상태를 동시에 다룰 때 useState보다 구조적이고 확장성이 좋다.

## 3. React.lazy와 Suspense 컴포넌트를 사용하는 리액트 애플리케이션에서 지연 로딩을 어떻게 구현할 수 있나요?

### `보경`

- React.lazy로 느리게 가져올 컴포넌트르 명시적으로 지정하고, Suspense로 감싸 컴포넌트가 로드중일 때 보여줄 수 있는 fallbackUI를 렌더링한다.

### `미림`

React.lazy를 사용하여 당장 화면에 렌더되지 않는 컴포넌트를 지연 로딩할 수 있습니다. 이렇게 지연 로딩한 컴포넌트는 화면에 렌더링 되어야 할 때 비로소 로드되기 시작하는데, 이때 Suspense를 사용하여 렌더링이 완료될 때까지 폴백 UI를 제공하여 UX를 향상할 수 있습니다.

### `정욱`

- 초기 렌더링에 필요하지 않은 컴포넌트의 Promise를 반환하는 함수를 `React.lazy`에 전달하여 해당 컴포넌트를 렌더링하기 위한 코드를 지연 로딩할 수 있음
- 해당 컴포넌트가 렌더링 가능하기 전까지 `Suspense`로 감싸 해당 `Suspense`에 전달된 fallback UI를 렌더링하여 사용자에게 어떤 작업이 진행되고 있는지 안내할 수 있음


### `영은`

React.lazy로 컴포넌트를 동적으로 불러오고, Suspense로 로딩 상태를 처리하면 필요한 시점에만 코드가 로드되어 초기 번들 크기를 줄이고 렌더링 속도를 최적화할 수 있다.



## 4.리액트에서 메모화를 사용할 떄 발생할 수 있는 잠재적 문제는 무엇이며 어떻게 완화할 수 있을까요?

### `보경`

- 메모화 된 컴포넌트의 props으로 전달된 상태 내부 값이 달라지지 않았음에도 불구하고, 함수나 객체의 참조값이 바뀌어 불필요하게 컴포넌트를 렌더링하는 문제가 있다.
- 해결방법 : props이 배열이나 객체라면 useMemo, 함수라면 useCallback으로 메모화 해 참조값을 기억한다.

### `미림`

💬잠재적 문제? 메모리? 남용? 잘못된 사용? 호스트 컴포넌트 메모? 뭘 말하는 거지.. 이게 잠재적인가?

불필요한 메모화나 제대로 메모화하지 않은 경우에는 메모화가 오히려 성능 저하를 유발할 수 있습니다. 예를 들어 React.memo로 컴포넌트를 메모화해도 객체 프롭을 메모화하지 않거나, 비용이 비싸지 않은 컴포넌트를 메모화하는 등의 경우 불필요한 프롭 비교 연산만 추가되는 격입니다. 따라서 리액트의 메모화는 연산 혹은 렌더링 비용이 비싸서 과정을 건너뛰어야 할 때 사용을 고려해야 합니다.

### `정욱`

- 전달받는 props가 참조 타입인 경우 해당 prop의 각 항목 값이 변경되지 않았다고 해도 매번 다른 것으로 간주하여 불필요한 리렌더링을 야기함
- 데이터의 경우 `useMemo`, 함수의 경우 `useCallback` hooks를 사용하여 이러한 문제를 완화할 수 있음

### `영은`

메모화는 참조 타입 프롭에 대해 매번 다른 값으로 인식되어 오히려 불필요한 비교 연산이나 재생성이 발생할 수 있으며, 이를 방지하기 위해 useMemo, useCallback을 활용해 참조 값을 안정화시킨다.

## 5. 리액트에서 컴포넌트에 프롭으로 전달된 함수를 메모화하기 위해 useCallback 훅을 어떻게 사용할 수 있나요?

### `보경`

함수를 정의할때 useCallback으로 한번 감싸준다.

### `미림`

부모 컴포넌트에서 함수를 프롭으로 전달하면, 부모 컴포넌트가 리렌더링되었을 때 함수가 재생성됩니다. 자식 컴포넌트를 React.memo로 메모화했어도 프롭으로 함수를 받는다면 항상 새로운 함수를 받게 되므로 불필요한 리렌더링이 발생합니다. useCallback으로 함수를 메모화한 후 프롭으로 전달하면, 의존성이 변경되지 않는 한 메모화한 자식 컴포넌트에 항상 같은 함수를 전달할 수 있습니다.

### `정욱`

- `React.memo`로 최적화되어있는 하위 컴포넌트에 콜백을 전달할 때 `useCallback`으로 감싼 함수를 전달하면 해당 함수와 관계없는 변경으로 이루어진 리렌더링 시 하위 컴포넌트가 불필요하게 리렌더링되지 않음

### `영은`

useCallback(fn, deps)을 사용하면 의존성이 변하지 않는 한 같은 함수 인스턴스를 재사용할 수 있어 렌더링마다 함수가 새로 생성되는 것을 방지하고, 자식 컴포넌트의 불필요한 렌더링을 줄일 수 있다.
