# 🎊 복습하기

## 1. 리액트의 파이버 재조정자는 무엇이며, 복잡한 고성능 애플리케이션을 처리하는 데 어떻게 도움이 되나요?

### `미림`
- 파이버 재조정자는 작업을 파이버(Fiber)라는 작은 단위로 나누어 효율적으로 처리합니다. 파이버 구조 덕분에 렌더링을 중간에 멈추거나 재개할 수 있고, 동시성 렌더링도 가능합니다. 복잡한 고성능 애플리케이션에서도 우선순위가 높은 작업부터 처리할 수 있어 궁극적으로 애플리케이션의 응답성을 높일 수 있습니다.

### `정욱`
- 리액트의 파이버 재조정자는 동시성 렌더링을 가능케 하는 리액트의 핵심 메커니즘
- 렌더링 프로세스를 파이버라고 하는 작업 단위로 분할해 처리
- 렌더링 작업을 일시적으로 중지 및 재개하거나 우선순위에 따라 스케줄링하거나 지연해 응답성과 성능을 개선할 수 있음

### `영은`
- 렌더링을 쪼개서 처리하게 해주는 리액트의 엔진. 복잡한 앱에서도 끊기지 않게 만든다.

## 2. 리액트에서 업데이트 예약 및 지연의 개념을 설명하세요. 부하가 많은 상황에서도 원활한 사용자 경험을 유지하는 데 어떻게 도움이 되나요?

### `미림`
- 리액트는 부하가 많은 상황에서도 애플리케이션의 응답성을 높이기 위해 중요한 업데이트를 먼저 스케줄링하고, 덜 중요한 업데이트는 우선순위를 낮춰 나중에 스케줄링되도록 지연하는 방식을 사용합니다.

### `정욱`
- 예약: 해야 할 갱신 작업이 있을 때 여러 API(브라우저 API 등)를 사용해서 작업이 처리될 타이밍을 예약/관리함
- 지연: 사용자 상호 작용을 우선시해 응답성을 유지하기 위해 중요하지 않은 갱신의 우선순위를 낮춤

### `영은`
- 우선순위가 낮은 업데이트를 예약하여 브라우저가 한가할 때 실행함으로써, 중요한 사용자 인터랙션을 빠르게 반영하고 부하가 큰 작업은 지연 처리

## 3. 리액트의 렌더 레인이란 무엇이며, 업데이트 실행을 어떻게 관리하나요? 렌더 레인이 비트마스크를 사용해 여러 우선순위를 처리하는 방법을 설명하세요.

### `미림`
- 렌더 레인은 렌더링 우선순위를 결정하는 메커니즘입니다. 레인이란 우선순위 수준을 나타내는 단위로 여러 종류가 있습니다. 중요한 업데이트일수록 우선순위가 높은 레인에 할당되며, 각 레인은 우선순위대로 처리됩니다.
- 비트마스크를 사용해 우선순위를 확인하는 등의 작업을 매우 빠르게 처리합니다. (아래 예시 참고)

```js
const SyncLane        = 0b0000000000000000000000000000001; // 즉시 업데이트
if ((currentLanes & SyncLane) !== 0) {
  // 현재 작업 중에 SyncLane이 포함되어 있음
}
```

### `정욱`
- 작업의 우선순위 수준을 나타내는 단위, 리액트가 렌더링 주기에서 처리할 수 있는 작업
- 예약된 갱신들을 수집해서 우선순위에 따라 레인에 할당한 후 우선순위가 가장 높은 레인부터 같은 레인의 갱신을 일괄 처리

### `영은`
- 업데이트마다 우선순위를 지정하는 시스템. 중요한 걸 먼저 처리하게 한다. 

## 4. 리액트에서 useTransition과 useDeferredValue 훅을 사용하는 목적은 무엇인가요? 각 훅이 유용한 상황을 설명하세요.

### `미림`
- useTransition: 덜 중요한 업데이트의 렌더링 우선순위를 낮춰 중요한 업데이트를 우선 처리하기 위해 사용합니다. 사용자의 상호작용을 차단하지 않는 동시에 백그라운드에서 업데이트 처리를 해야 할 때 유용합니다.
- useDeferredValue: 렌더링과 관련된 업데이트를 디바운싱처럼 지연했다가 처리해야 할 때 사용합니다. 예를 들어 대규모 데이터 검색이나 사용자 상호작용이 일어날 때마다 무거운 작업을 처리해야 하는 경우처럼, 비용이 높은 작업의 실행 횟수를 최소화해야 할 때 유용합니다.

### `정욱`
- `useTransition`은 `useDeferredValue`는 모두 우선순위를 관리하는 hook
- `useTransition`은 시각적으로 혼란을 줄 수 있는 갱신을 처리할 때 유용함
- `useDeferredValue`는 연산이 많이 이루어져야 하는 작업을 처리해야 하는 애플리케이션을 최적화할 때 유용함

### `영은`
- 트랜지션은 상태 변경을 늦추는 거고, 디퍼드는 값은 바로 바뀌지만 렌더링만 늦게하는것

## 5. useDeferredValue를 사용하는 것이 부적절한 상황은 어떤 상황일까요? 이 훅을 사용할 때 고려할 장단점은 무엇인가요?

### `미림`
- useDeferredValue 훅을 사용하면 새 상태에 대한 렌더링을 진행하는 동안 이전 상태 렌더링 결과를 사용하게 됩니다. 로딩 UI를 중간에 거치지 않아서 더 매끄러운 UX를 제공할 수 있지만, 오래된(stale) 렌더링 결과를 제공하게 된다는 단점이 있습니다.
- 이러한 특징 때문에 사용자 상호작용에 의한 업데이트를 지연할 때에만 사용하는 것이 적절합니다. 그렇지 않은 경우, 예를 들어 백그라운드에서 데이터가 들어오고 있는데 이를 지연하면 최신 데이터가 있음에도 UI가 일부러 느리게 갱신됩니다.

### `정욱`
- 사용자가 즉각적인 반응을 원하는 갱신인 경우 `useDeferredValue`를 사용해 갱신을 지연하는 것은 부적절함
- 애플리케이션이 사용자 입력에 대한 갱신을 우선 처리할 수 있어 응답성을 유지할 수 있다는 장점이 있음
- 이에 반해 사용자가 오래된 데이터를 보게 될 수 있다는 단점이 있음

### `영은`
- 입력값과 화면 출력이 즉시 동기화돼야 하는 UI에는 부적절
