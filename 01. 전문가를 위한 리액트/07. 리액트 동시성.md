# 7장 리액트 동시성

7.1 동기식 렌더링의 문제

- 자바스크립트는 싱글 스레드 언어로, 한 번에 하나의 작업만 실행할 수 있다.
- 비동기적으로 처리하는 기능들(`setTimeout`, `Promise` 등)을 통해 일괄처리로 병목을 어느 정도 피할 수 있지만, 작업 간 우선순위를 지정하는 기능은 없다.
- 이로 인해, 사용자 인터랙션처럼 중요한 작업이, 화면 업데이트나 기타 덜 중요한 작업에 의해 지연될 수 있는 문제가 발생한다.
- 리액트는 이러한 문제를 해결하기 위해 동시성 렌더링 개념을 도입했고,

  업데이트 작업마다 우선순위를 부여하고 스케줄링하는 방식으로 개선했다.

- 리액트는 이제 렌더링 작업을 한 번에 처리하지 않고, 작업을 쪼개어 필요한 경우 중단할 수 있는 방식을 채택한다.
- 이는 다음과 같은 장점을 가진다: - 우선순위가 높은 작업(예: 사용자 입력)을 먼저 처리할 수 있다. - 전체 UI를 한 번에 그리는 대신, 부분적으로 점진적 렌더링이 가능하다. - 작업을 실행 중에도 중단하고 나중에 재개할 수 있어, 긴급한 작업을 먼저 처리할 수 있다.

  7.3 업데이트 예약과 지연

예시: 실시간 채팅 애플리케이션

- 사용자가 메시지를 입력하는 상황을 예로 들면,
  - 텍스트 입력은 사용자와의 직접적인 상호작용이므로 우선순위가 높은 작업이다.
  - 반면, 채팅 목록을 다시 렌더링하는 작업은 우선순위가 낮은 작업이다.
- 리액트는 이러한 작업들을 동일한 흐름으로 처리하지 않고, 분리하여 우선순위에 따라 실행한다.
- 이때 사용하는 도구 중 하나가 `useTransition` 훅인데,

      이는 낮은 우선순위의 상태 업데이트를 명시적으로 구분할 수 있게 해준다. (이 내용은 이후 장에서 더 상세히 다룸)

  7.4 스케줄러

💬 렌더레인 모르는데 자꾸 렌더레인거려서 뭐지 싶었음…

- 스케줄링은 작업을 예약하는 것이며, 실제 처리 여부는 각 레인의 우선순위나 만료 여부에 따라 결정됨.

  7.5 렌더레인

- 렌더 레인은 리액트의 렌더링 과정에서 업데이트의 우선순위를 관리하기 위한 단위임.
- 업데이트가 발생하면 해당 작업은 특정 레인에 할당됨.
- `setState()`가 클릭 핸들러 내부에서 호출될 경우, 가장 높은 우선순위인 `SyncLane`에 배정됨.
- 이 외에도 다양한 레인(SyncLane, TransitionLane, RetryLane 등)이 존재하며,
  작업의 성격에 따라 다른 레인으로 분류됨.
