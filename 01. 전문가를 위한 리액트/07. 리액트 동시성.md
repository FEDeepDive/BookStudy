# 7장 리액트 동시성

7.1 동기식 렌더링의 문제

- 자바스크립트는 싱글 스레드 언어로, 한 번에 하나의 작업만 실행할 수 있다.
- 비동기적으로 처리하는 기능들(`setTimeout`, `Promise` 등)을 통해 일괄처리로 병목을 어느 정도 피할 수 있지만, 작업 간 우선순위를 지정하는 기능은 없다.
- 이로 인해, 사용자 인터랙션처럼 중요한 작업이, 화면 업데이트나 기타 덜 중요한 작업에 의해 지연될 수 있는 문제가 발생한다.
- 리액트는 이러한 문제를 해결하기 위해 동시성 렌더링 개념을 도입했고,

  업데이트 작업마다 우선순위를 부여하고 스케줄링하는 방식으로 개선했다.

- 리액트는 이제 렌더링 작업을 한 번에 처리하지 않고, 작업을 쪼개어 필요한 경우 중단할 수 있는 방식을 채택한다.
- 이는 다음과 같은 장점을 가진다: - 우선순위가 높은 작업(예: 사용자 입력)을 먼저 처리할 수 있다. - 전체 UI를 한 번에 그리는 대신, 부분적으로 점진적 렌더링이 가능하다. - 작업을 실행 중에도 중단하고 나중에 재개할 수 있어, 긴급한 작업을 먼저 처리할 수 있다.

  7.3 업데이트 예약과 지연

예시: 실시간 채팅 애플리케이션

- 사용자가 메시지를 입력하는 상황을 예로 들면,
  - 텍스트 입력은 사용자와의 직접적인 상호작용이므로 우선순위가 높은 작업이다.
  - 반면, 채팅 목록을 다시 렌더링하는 작업은 우선순위가 낮은 작업이다.
- 리액트는 이러한 작업들을 동일한 흐름으로 처리하지 않고, 분리하여 우선순위에 따라 실행한다.
- 이때 사용하는 도구 중 하나가 `useTransition` 훅인데,

      이는 낮은 우선순위의 상태 업데이트를 명시적으로 구분할 수 있게 해준다. (이 내용은 이후 장에서 더 상세히 다룸)

  7.4 스케줄러

💬 렌더레인 모르는데 자꾸 렌더레인거려서 뭐지 싶었음…

- 스케줄링은 작업을 예약하는 것이며, 실제 처리 여부는 각 레인의 우선순위나 만료 여부에 따라 결정됨.

  7.5 렌더레인

- 렌더 레인은 리액트의 렌더링 과정에서 업데이트의 우선순위를 관리하기 위한 단위임.
- 업데이트가 발생하면 해당 작업은 특정 레인에 할당됨.
- `setState()`가 클릭 핸들러 내부에서 호출될 경우, 가장 높은 우선순위인 `SyncLane`에 배정됨.
- 이 외에도 다양한 레인(SyncLane, TransitionLane, RetryLane 등)이 존재하며,
  작업의 성격에 따라 다른 레인으로 분류됨.

  7.6 `useTransition`

<aside>

컴포넌트에서 상태 업데이트의 우선순위를 관리하고, 우선순위가 높은 업데이트로 인해 ui가 응답하지 않는 것을 방지하는 훅

</aside>

- 매개변수 x
- 반환값: `[isPending,startTransition]`
  - `startTransition(callback)`
    - `callback` 내부의 상태 업데이트는 **낮은 우선순위로 실행**
    - 함수 호출 중에 동기적으로 예약된 모든 상태 업데이트를 Transitions으로 표시
  - `isPending`
    - 현재 트랜지션 작업이 진행 중이면 `true`
    - 로딩 UI를 보여줄 때 사용
- 책예시: 페이지 전환
  SPA 구조에서는 페이지 전환도 사실은 상태 변경이 일어나는것 (새로운 컴포넌트 렌더링)
  무거운 컴포넌트가 렌더링되면 화면이 잠깐 멈추거나, 클릭해도 아무 반응이 없는 듯한 느낌이 들수있음 ⇒ 사용자 경험을 나쁘게 만듬 ⇒ useTransition을 사용해 리액트의 렌더링 스케줄 자체를 바꿔서 사용자 입력/클릭과 무거운 렌더링 작업을 분리함 (사용자 인터렉션을 먼저 처리 /트랜지션 내부의 상태변경은 브라우저가 여유있을때 처리) ⇒ 사용자 경험 상승
- ! 렌더링이 느려지는 걸 방지할 뿐 **비동기 fetch 자체를 느리게 하거나 빠르게 만들진 않음**
- 트랜지션 안에서 Suspense 기반의 컴포넌트를 렌더링하면, fetch나 렌더링 완료까지 `isPending` 상태가 유지됨

  7.7 `useDeferredValue`

- 특정 ui업데이트를 나중으로 미루는데 사용되는 훅/ 덜 중요한 업데이트의 렌더링을 지연하는 훅
- 매개변수 : `value` ,`_initialValue`
  - `value` : 지연시키려는 값
  - `initialValue?` : 컴포넌트 초기 렌더링 시 사용할 값(선택사항)
- 반환값 : currentValue
  - currentValue: 낮은 우선순위 lane으로 스케줄됨
- Debounce / Throttle과의 차이점
  |               | `useDeferredValue`                      | Debounce / Throttle                            |
  | ------------- | --------------------------------------- | ---------------------------------------------- |
  | 제어 대상     | **렌더링 타이밍**                       | **값의 변경 자체**                             |
  | 입력 반응성   | 항상 즉각적 (`input`은 즉시 업데이트됨) | 입력 반영 자체가 느려짐 (타이머 지나야 반영됨) |
  | 렌더링 타이밍 | React가 스케줄링하여 여유 있을 때 실행  | 명시한 시간 후 실행 (비동기 타이머)            |
  | 응답성        | 좋음 (타이핑 중에도 버벅임 없음)        | 입력 반응이 느려져 UX에 지장 있음              |
  | 제어 방식     | 선언적 (React 내부 스케줄러)            | 명령형 (setTimeout, lodash 등 직접 제어)       |
  - **응답성 개선**
    입력 필드에서 타이핑은 즉시 반영되지만, 결과 렌더링은 부드럽게 지연됨
  - **선언적 우선순위 조절**
    개발자가 우선순위 높은 컴포넌트를 분리하지 않아도 됨 → 코드 깔끔
  - **리소스 활용 향상**
    불필요한 연산을 줄이고, 앱 전체 성능을 향상시킴
- 사용시기
  - 대규모 데이터 필터링/정렬 결과를 렌더링할 때
  - 입력 필드에서 입력값 변경 → 리스트 렌더링이 무거운 경우
  - 상태 업데이트는 빠르게 되지만, 렌더링은 늦게 처리하길 원할 때
- `useDeferredValue`는 “정답”이 아닌 선택지 중 하나일 뿐 → 필요할 때만 사용, 코드 복잡도 고려해야함 - 💬 은탄환은 없다는 말이 생각남

          > 도구에 집착하기보다는 문제를 먼저 정확히 정의하고, 거기에 필요한 만큼, 적절한 시점에 필요한 도구를 적용하자
          >

  7.8 동시성 렌더링 관련 문제

- 티어링
  - 동시성 렌더링 중 상태가 일관되지 않게 보이는 버그
  - 동기식렌더링 vs 동시성렌더링
    - 동기식 : 순차적으로 렌더링
    - 동시성: 렌더링을 쪼개서 함
      - 같은 상태인데, 두 컴포넌트가 서로 다른 값을 볼 수있음 ⇒ 티어링!
- `useSyncExternalStore`
  - 외부 store를 구독할 수 있는 훅
  - 리액트는 동시성 환경에서도 상태를 일관되게 가져가고 싶었음
  - 매개변수: `subscribe`,`getSnapshot`,`getServerSnapshot?`
    - `subscribe` : `callback` 인수를 받아 store에 구독하는 함수 (외부 상태가 바뀌면 리액트에게 알리는 함수)
    - `getSnapshot` : 외부 상태의 현재 값을 반환하는 함수(컴포넌트에 필요한 store 데이터의 스냅샷을 반환하는 함수)
    - `getServerSnapshot?` : SSR에서 사용할 스냅샷 (선택사항)
  - 스냅샷을 미리 고정해두고,→ 모든 컴포넌트가 같은 값을 기반으로 렌더링

🎊복습하기

1. **리액트의 파이버 재조정자는 무엇이며, 복잡한 교층형 애플리케이션을 처리하는 데 어떻게 도움이 되나요?**

   렌더링을 쪼개서 처리하게 해주는 리액트의 엔진. 복잡한 앱에서도 끊기지 않게 만든다.

2. **리액트의 업데이트 예약 및 지연의 개념을 설명하세요. 부하가 많은 상황에서도 원활한 사용자 경험을 제공하는 데 어떻게 도움이 되나요?**

   우선순위가 낮은 업데이트를 예약하여 브라우저가 한가할 때 실행함으로써, 중요한 사용자 인터랙션을 빠르게 반영하고 부하가 큰 작업은 지연 처리

3. **리액트의 렌더 레인이란 무엇이며, 업데이트 실행을 어떻게 관리하나요? 렌더 레인에 비트마스크를 사용하여 우선순위를 처리하는 방법을 설명하세요.**

   업데이트마다 우선순위를 지정하는 시스템. 중요한 걸 먼저 처리하게 한다.

4. **리액트에서 useTransition과 useDeferredValue 훅을 사용하는 목적은 무엇인가요? 각 훅이 유용한 상황을 설명하세요.**

   트랜지션은 **상태 변경**을 늦추는 거고, 디퍼드는 **값**은 바로 바뀌지만 렌더링만 늦게하는것

5. **useDeferredValue를 사용하는 것이 부적절한 상황은 어떤 상황일까요? 이 훅을 사용할 때 고려할 점은 무엇인가요?**

   입력값과 화면 출력이 즉시 동기화돼야 하는 UI에는 부적절
