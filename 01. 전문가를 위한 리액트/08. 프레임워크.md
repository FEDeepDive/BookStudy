## 8.1 프레임워크가 필요한 이유
- 리액트는 특정 아키텍처를 강요하지 않으므로 개발자가 적합하다고 생각하는 방식대로 애플리케이션을 구성할 수 있음
- 애플리케이션의 규모가 커질수록 라우팅, 데이터 획득, 서버 사이드 렌더링 등의 일반적인 문제를 반복하여 다뤄야 할 때가 옴
- 프레임워크는 미리 정의된 구조와 일반적인 문제에 대한 해결책을 제공하므로 반복 작성해야 하는 코드에 얽매이지 않고 애플리케이션의 고유한 기능에 집중할 수 있음
- (#) 리액트의 등장으로 "무엇을 보여줘야 할지"만 생각할 수 있게 된 것과 비슷하게, "무엇을 할지"만 생각할 수 있게 되었다는 의미겠지요

## 8.4 인기있는 리액트 프레임워크
### 8.4.1 Remix
- (#) Remix는 2025년 현재 React Router v7과 통합되어 더 이상 해당 이름을 사용하지 않는 것으로...
- 서버 렌더링을 처리하는 데 내부적으로 사용되는 코드가 노출되어 있어 필요에 따라 수정 가능함
- (#) 별도의 패키지를 통해 파일 기반 라우팅을 사용할 수 있음!
- 데이터 획득을 위한 `loader` 함수를 내보내면 `useLoaderData` hook을 통해 컴포넌트에서 획득한 데이터를 사용 가능
  - (#) RR7의 프레임워크 모드를 사용하면 `clientLoader` 함수를 통해 클라이언트 컴포넌트에서도 데이터 획득이 가능!
- 별도로 리액트를 통해 작업을 처리하는 방법도 있지만 네이티브 웹 플랫폼의 규칙과 동작을 적극 활용하도록 유도함
  - `params`와 `request` 인자를 받는 `action` 함수를 통해 API에 요청을 날릴 수 있음
    - (#) RR7에서는 `loader`와 마찬가지로 `clientAction` 함수도 존재함
### 8.4.2 Next.js
- 개발자가 직접 설명해야 할 항목을 최소화하고 기본값을 제공해 생산성을 높임
- 서버 렌더링을 제공할 뿐만 아니라 서버 우선, 정적 우선 접근 방식을 따름
- 파일 기반 라우팅이지만, 디렉토리가 하나의 페이지로 간주되며 실제 페이지 파일은 항상 동일한 이름으로 정의되어야 함
- 컴포넌트 내부에서 직접 데이터를 획득할 수 있음

## 8.5 프레임워크 선택
- 프레임워크마다 강점과 약점이 있으며 요구사항과 개발자의 선호도에 따라 프로젝트에 가장 적합한 프레임워크가 달라짐
- 다소 유연한 풀스택 프레임워크가 핗요하다면 Next.js가 더 적합할 수 있음
  - (#) 이 부분 절대 동의하지 않습니다!!! Next.js는 Next.js가 원하는 형태의 코드 구조와 배포 환경을 따를 때만 100%의 힘을 발휘합니다...
- 웹의 기본 원칙을 중시하는 접근 방식을 선호한다면 Remix가 어울릴 수 있음
  - (#) 이 말은 곧 웹을 벗어나는 환경... 가령 앱이나 데스크탑 프로그램이라면 적용하기 어렵다는 말이겠죠
- Next.js는 기본적으로 정적 생성을 사용하며 전체 재빌드 없이도 정적 페이지를 재생성할 수 있는 증분 정적 재생성 기능을 도입하여 대규모 동적 사이트의 빌드 시간을 크게 개선함
  - (#) 이 때 정적 페이지로 생성되면 안되는 페이지는 동적으로 사용하겠다고 잘 선언해줍시다...

## 8.7 복습하기
- Next.js나 Remix 같은 리액트 프레임워크를 사용하는 주된 이유와 이때 얻는 장점은 무엇인가요?
  - 애플리케이션의 규모가 커질수록 제품에 직접적이지 않은 일반적인 문제를 반복해서 다루게 됨
  - 프레임워크는 이러한 일반적인 문제에 대한 해결책을 모아놓았기 때문에 제품 자체에 집중할 수 있게 됨
- 리액트 프레임워크를 사용할 때 생기는 장단점이나 불리한 점에는 어떤 것이 있나요?
  - 개발자가 따를 것을 권장하는 모범 사례를 제공하기 때문에 코드 품질을 향상시킬 수 있으며, 기본으로 제공하는 최적화 기능을 통해 더 나은 성능과 사용자 경험을 줄 수 있음
  - 그러나 프레임워크 자체의 학습 곡선이 존재하며 프레임워크의 모델과 맞지 않는 요구사항을 충족해야 할 경우 고통스러운 개발 경험을 하게 될 수 있음
- 프레임워크로 해결되는 일반적인 문제에는 어떤 것이 있나요?
  - 라우팅, 데이터 획득, 서버 측 렌더링 등이 있음
- 프레임워크는 이런 문제를 어떻게 해결하나요?
  - 프로젝트 디렉토리 구성에 특정한 규칙이 존재할 경우 이에 따라 파일 기반 라우팅을 적용하여 확장성을 높일 수 있음
  - 파일이 필요로 하는 데이터를 클라이언트가 아닌 서버에서 미리 획득한 후 컴포넌트에 전달하여 네트워크 폭포 현상을 완화할 수 있음
  - 전체 페이지를 서버에서 미리 렌더링한 후 클라이언트에 전송하여 초기 페이지에 내용을 채워 사용자에게 의미있는 화면을 보여줄 수 있음
