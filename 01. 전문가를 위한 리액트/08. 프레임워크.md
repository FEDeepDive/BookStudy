# 🎊 복습하기

## 1. Next.js나 Remix 같은 리액트 프레임워크를 사용하는 주된 이유와 이때 얻는 장점은 무엇인가요?

### `미림`

- 리액트 프레임워크를 사용해 리액트를 사용했을 때 겪을 수 있는 일반적이고 반복되는 패턴이나 문제들을 쉽게 해결할 수 있습니다. Next.js나 Remix 등 리액트 프레임워크를 통해 서버 사이드 렌더링, 라우팅, 데이터 페치 등의 기능을 제공받고, 제품과 기능에만 집중할 수 있습니다.

### `정욱`

- 애플리케이션의 규모가 커질수록 제품에 직접적이지 않은 일반적인 문제를 반복해서 다루게 됨
- 프레임워크는 이러한 일반적인 문제에 대한 해결책을 모아놓았기 때문에 제품 자체에 집중할 수 있게 됨

### `영은`

- 라우팅, 데이터페칭 등을 일관된 방식으로 제공해주며, SEO, 접근성, 성능 최적화에 대한 기본적인 고민을 줄여줌 또한 서버와 클라이언트를 넘나드는 통합된 개발 경험을 제공

## 2. 리액트 프레임워크를 사용할 때 생기는 장단점이나 불리한 점에는 어떤 것이 있나요?

### `미림`

- 장점으로는 편의성이 있습니다. 리액트 프레임워크가 반복적인 문제에 대한 해결책을 추상화하여 제공하므로 개발자는 애플리케이션 개발에만 집중할 수 있습니다. 또 커뮤니티가 잘 마련되어 있는 경우 문제가 생겼을 때 도움을 받기 쉽습니다.

- 단점으로는 학습 곡선과 제약이 있습니다. 프레임워크를 사용하려면 해당 프레임워크의 규칙, 제공하는 문법, 설계 철학 등을 학습해야 합니다. 프레임워크의 규칙에 따라 개발하는 게 제약이라고 느껴질 수도 있습니다.

### `정욱`

- 개발자가 따를 것을 권장하는 모범 사례를 제공하기 때문에 코드 품질을 향상시킬 수 있으며, 기본으로 제공하는 최적화 기능을 통해 더 나은 성능과 사용자 경험을 줄 수 있음
- 그러나 프레임워크 자체의 학습 곡선이 존재하며 프레임워크의 모델과 맞지 않는 요구사항을 충족해야 할 경우 고통스러운 개발 경험을 하게 될 수 있음

### `영은`

- 위에랑 비슷한 질문같은데 장점은 기본적으로 제공되는 기능(라우팅, SEO 등)들 덕분에 개발자가 편리하게 개발할 수 있음. 단점은 러닝커브가 있고, 자유도가 떨어짐

## 3. 프레임워크로 해결되는 일반적인 문제에는 어떤 것이 있나요?

### `미림`

- 리액트는 기본적으로 CSR이기 때문에 SEO에 불리합니다.
- 데이터 페치 시점이 너무 늦습니다. 컴포넌트가 마운트된 이후에 데이터 페치가 가능합니다.

### `정욱`

- 라우팅, 데이터 획득, 서버 측 렌더링 등이 있음

### `영은`

- 라우팅 관리,서버사이드 렌더링/정적 사이트 생성,데이터 패칭 흐름 통일,에러 핸들링, 로딩 상태 관리,SEO 최적화. 이런 공통 문제들을 개발자가 직접 구현할 필요 없이 프레임워크가 기본 제공하므로, 빠르고 안정적인 제품 개발이 가능해진다.

## 4. 프레임워크는 이런 문제를 어떻게 해결하나요?

### `미림`

- Next.js, Remix 같은 리액트 프레임워크는 SSR과 효율적인 데이터 페치 방식을 제공해 리액트의 CSR로 인한 문제를 해결합니다. 이외에도 라우팅 방식이나 코드베이스, 파일 구조 등을 규칙으로 정해 의사 결정 시간을 단축할 수 있으며, 캐싱이나 코드 분할 등의 성능 최적화를 지원하기도 합니다.

### `정욱`

- 프로젝트 디렉토리 구성에 특정한 규칙이 존재할 경우 이에 따라 파일 기반 라우팅을 적용하여 확장성을 높일 수 있음
- 파일이 필요로 하는 데이터를 클라이언트가 아닌 서버에서 미리 획득한 후 컴포넌트에 전달하여 네트워크 폭포 현상을 완화할 수 있음
- 전체 페이지를 서버에서 미리 렌더링한 후 클라이언트에 전송하여 초기 페이지에 내용을 채워 사용자에게 의미있는 화면을 보여줄 수 있음

### `영은`

- 미리 설계된 구조와 추상화된 API를 통해 공통 문제들을 해결
