### 1. 프레임워크가 필요한 이유

리액트는 자유도가 높아 라우팅, 데이터 페치, SSR등 일반적인 문제를 반복해야할 수 있다. 프레임워크가 이를 대신 해준다.

CSR에서는:

- React Router가 클라이언트에서 작동함
- `build/index.html` 하나만 보내주면
- 브라우저가 JS를 실행해서 URL에 맞는 화면을 클라이언트에서 "렌더링"함

그러나 SSR에서는:

- JS가 **브라우저에서 실행되기 전**에, 서버가 **미리 HTML을 만들어서 보내줘야 함**
- 즉, URL마다 서버가 직접 `<App />`을 렌더링해야 함
- 따라서 서버는 각 URL 요청에 맞춰 React 컴포넌트를 "렌더링"하고 HTML을 생성해야 함

### 2. 프레임워크 사용 시 장/단점

- 장점
  - 특정 구조와 패턴이 있을 사용해야 일관적임
  - 라우팅, 데이터페칭, 서버렌더링 등의 작업에 높은 수준의 추상화를 제공함
  - 성능최적화가 잘 되어있음
- 단점
  - 러닝커브가 있다.

### 3. 프레임워크를 선택할 때 고려해야 할 기준

- 라우팅은 어떻게 구현할 것인지
- 정적 자산은 어디에 둘 것인지
- 서버렌더링이 필요한지
- 데이터 페칭은 어디서 실행할 것인지
