# 🎊 복습하기

## 1. 리액트 서버 컴포넌트의 주된 가치는 무엇인가요?

### `보경`

- 자바스크립트 번들 크기를 줄여주고, 민감한 데이터를 서버에서 다룰 수 있다.

### `미림`

- 서버에서만 렌더링할 컴포넌트와 클라이언트에서만 렌더링할 컴포넌트를 나눔으로써 성능을 향상시킬 수 있다는 것입니다. 이 성능 향상은 사용자 경험 개선으로 이어집니다.

### `정욱`

- 파일 시스템에서 데이터를 읽거나 비동기 함수를 기다리는 등 기존 클라이언트 컴포넌트로는 불가능했던 작업을 가능케 함
- 실제로 상호작용을 처리하는 코드만 클라이언트 번들에 포함시켜 성능을 높이고 다운로드해야 하는 데이터 양을 줄일 수 있음

### `영은`

- 서버에서 처리할 수 있는건 서버에서 미리 처리해서 클라이언트의 부담을 줄여주는게 주된 가치.

## 2. 클라이언트 컴포넌트가 서버 컴포넌트를 가져올 수 있나요? 그렇게 답변한 이유가 무엇인가요?

### `보경`

- 못 가져온다. 서버 컴포넌트는 서버에서 실행되기 때문에 컴포넌트 내부에서 서버 환경에서만 사용할 수 있는 특정 기능을 사용할 수도 있다. 이런 서버 컴포넌트를 클라이언트에서 렌더링 하게 되면 문제가 발생한다.

### `미림`

- 클라이언트 컴포넌트는 서버 컴포넌트를 import할 수 없습니다. 클라이언트 컴포넌트가 서버 컴포넌트를 가져오면 해당 서버 컴포넌트도 클라이언트 자바스크립트 번들에 포함되는데, 서버 컴포넌트에는 클라이언트가 이해하지 못하는 코드가 있을 수 있기 때문입니다.

### `정욱`

- 클라이언트 컴포넌트는 서버 컴포넌트를 `import`할 수 없음
- 서버 컴포넌트는 클라이언트 환경에서 사용할 수 없는 요소를 포함할 수 있기에 오류가 발생하기 때문
- 대신 `props`를 통해 조합하는 것은 가능

### `영은`

- no. 서버컴포넌트는 서버에서만 실행 할 수 있음.

- 클라이언트 컴포넌트는 브라우저에서 실행되기 때문에 서버컴포넌트를 포함 할 수 없음

## 3. 서버 컴포넌트와 기존 클라이언트 전용 리액트 애플리케이션 사이에는 어떤 트레이드오프가 있나요?

### `보경`

- 보안문제가 있음

### `미림`

- 기존에는 컴포넌트가 항상 클라이언트 측에서 렌더링되므로 이와 관련해서 개발할 때 유의할 점이 없습니다. 그러나 서버 컴포넌트의 경우 서버 컴포넌트와 클라이언트 컴포넌트가 나뉘어 있고, 각각의 역할이 있으므로 이를 유의하며 개발해야 합니다. 두 컴포넌트 사이 경계를 나누기 어려울 수 있습니다.

### `정욱`

- 서버 컴포넌트는 UI를 빠르게 보여주며 웹사이트의 성능을 높일 수 있지만 복잡한 사용자 상호작용을 처리할 수 없고 브라우저 API를 사용할 수 없음
- 클라이언트 컴포넌트는 자유로운 사용자 상호작용 로직을 가질 수 있지만 자바스크립트 번들이 다운로드되고 나서야 처리를 시작할 수 있음

### `영은`

- 클라이언트 번들 크기 감소 및 성능 최적화를 할 수 있고, 보안적으로 우수하지만 구분해서 적어야 함..? 잘못하면 하이드레이션 오류를 만날 가능성이 높음?

## 4. 모듈 참조란 무엇이며, 리액트는 재조정 과정에서 모듈 참조를 어떻게 처리하나요?

### `보경`

- import 해서 가져오는것....ㅋㅋㅋ

### `미림`

- 서버 컴포넌트와 클라이언트 컴포넌트가 서버 측에서 렌더링될 때, 클라이언트 컴포넌트를 번들러가 참조하는 것을 말합니다. 리액트가 재조정 과정에서 해당 클라이언트 컴포넌트를 렌더링하기 위해 번들러가 참조한 모듈(=클라이언트 컴포넌트)을 가져와 실행하고, 이를 통해 참조한 모듈이 실제 모듈로 교체됩니다.

### `정욱`

- 서버 컴포넌트 렌더링 시 클라이언트에서도 렌더링되어야 하는 부분을 위해 렌더링한 placeholder
- 리액트는 클라이언트에서 이러한 placeholder를 만나면 전달받은 번들의 실제 모듈로 대체함

### `영은`

- 버 렌더링 중에 클라이언트 컴포넌트를 만나면, 리액트는 그걸 모듈 참조라고 부른다.
  이때 리액트는 $$typeof 값으로 이게 클라이언트 컴포넌트라는 걸 확인하고,
  해당 자리에 placeholder로 마킹만 해놓음(클라이언트 컴포넌트라 나중에 처리할거임 표시)
  그리고 서버에서는 서버 컴포넌트들만 먼저 쭉 렌더링해서 클라이언트에 스트리밍으로 전달한다.
  이후 브라우저에서는 placeholder를 보고 클라이언트 컴포넌트를 하이드레이션 해서 연결해준다.

## 5. 서버 액션은 어떤 방식으로 리액트 애플리케이션의 접근성을 향상시키나요?

### `보경`

- ‘use server’ 키워드 사용 후 클라이언트 컴포넌트에서 사용하듯이 함수를 넣어주면 서버에서 함수를 호출한다.

### `미림`

- 클라이언트 코드에서 서버 함수를 사용할 수 있게 만듭니다. 서버 액션을 통해 클라이언트 컴포넌트와 서버 컴포넌트 사이에서 유연하고 확장성 있게 개발할 수 있습니다.

### `정욱`

- 자바스크립트 번들이 전부 로드되기 전에도 서버 액션을 사용하여 폼을 사용하고 FormData를 전송하는 점진적 향상(Progressive enhancement) 전략을 적용할 수 있음

### `영은`

- 서버에서 html을 만들어서 보내주기 때문에 스크린리더가 전체 구조를 읽을 수 있어 접근성이 올라감.
