## 1. DOM이란 무엇이며, 가상 DOM과 어떻게 다른가요 ?

### `보경`

- DOM은 웹 어플리케이션이 어떻게 구성되어 있는지 나타내는 문서 객체 모델
- 가상 DOM은 실제 DOM을 추상화한 자바스크립트 객체

### `미림`

DOM은 문서 객체 모델로 HTML 문서를 노드 객체로 구조화한 것입니다. 가상 DOM과 가장 큰 차이점은 직접적으로 조작하여 변경 사항을 만들 경우 리플로우/리페인팅을 발생시킨다는 것입니다.

### `정욱`

DOM이란 HTML 문서를 자바스크립트 객체로 모델링했다는 점에서 가상 DOM과 같지만, DOM을 이루는 각 노드가 평범한 자바스크립트 객체가 아니라 특정한 인터페이스를 구현하여 추가적인 속성과 메소드를 가지는 객체라는 차이점이 있다!

### `영은`

그냥DOM : HTML 문서를 브라우저가 해석하여 계층적 구조(트리)로 표현한 객체 모델

가상DOM: React와 같은 라이브러리에서 사용하는 개념으로, 실제 DOM을 직접 조작하지 않고, 가상의 DOM을 메모리에 두고 변경 사항을 관리한다.

가상 DOM에 변경사항 맞춰 실제DOM을 변경시키는 것 ⇒ 재조정 ⭐️

## 2. 문서 조각이란 무엇이며, 리액트의 가상 DOM과 어떤 점에서 비슷하고 다른가요 ?

### `보경`

- 문서조각이란 웹 api를 통해 생성할 수 있는 문서 조각 객체로, 실제 DOM 트리의 일부가 아니라 리플로우를 트리거하지 않는다.
- 리플로우를 트리거하지 않기 때문에 DOM의 변경사항들을 문서 조각에서 일괄적으로 적용한다는 점이 가상DOM과 비슷함
- 이 때 가상DOM은 디핑알고리즘을 사용해 변경된 사항을 효율적으로 찾아내는 반면, 문서 조각은 변경된 요소를 포함한 내용을 적용하는 방식

### `미림`

문서 조각은 임시적인 객체 모델입니다. DOM처럼 노드 객체로 이루어져 있지만, DOM과 달리 메모리에서만 임시적으로 사용됩니다. 문서 조각에 노드 객체를 추가해 트리를 구성하고 DOM에 삽입하면, 여러 변경 사항을 일괄적으로 업데이트할 수 있습니다. 가상 DOM처럼 말입니다.

### `정욱`

문서 조각이란 DOM 트리의 일부분을 저장할 수 있으며, 실제 DOM에 영향을 주지 않으면서 여러 가지 갱신을 일괄적으로 수행할 수 있는 임시 저장소이다. 변경 사항을 일괄적으로 처리하기 때문에 reflow/repaint의 횟수를 줄일 수 있다는 점이 비슷하지만, 가상 DOM은 변경 사항을 효율적으로 반영하기 위해 필요한 계산 횟수를 계산할 수 있는 알고리즘을 적용할 수 있을 뿐만 아니라 여러 브라우저 간 동작의 일관성을 보장할 수 있다!

### `영은`

**문서조각**
DOM 노드를 저장하는 컨테이너
일괄처리, 성능개선

**가상돔**  
Diffing 알고리즘을 적용하여 변경된 부분만 업데이트하는 똑똑한 방식

## 3. DOM에서 문제가 되는 사안은 무엇인가요?

### `보경`

문서가 커질수록 리플로우/리페인팅에 비용이 많이 소모되어 UI가 지연될 가능성이 높다

### `미림`

- 성능
  - DOM이 변경될 때마다 리플로우/리페인팅이 발생 (레이아웃 스래싱도 발생 가능)
  - 특정 노드를 탐색할 때 DOM의 전체 트리를 탐색해야 할 수 있음
- 브라우저 간 호환성 유지 X
- 페이지 복잡성이 증가할수록 DOM API 쓰기 복잡해짐

### `정욱`

각 변경이 일어날 때마다 레이아웃을 다시 계산하고 그리는 데 드는 성능 문제, 여러 브라우저 간에 문서를 해석하여 나타내는 방식의 차이에서 발생하는 호환성 문제 등이 존재한다.

### `영은`

잦은 리페인트와 리플로우로 성능 저하이슈

<br>

## 4. 사용자 인터페이스를 더 빠르게 업데이트하는데, 가상 DOM이 어떻게 활용되나요 ?

### `보경`

- 가상 DOM의 디핑 알고리즘이 변경 사항을 빠르게 찾아내 일괄적으로 적용하는 재조정 알고리즘을 활용한다.
- 모든 UI를 다시 그릴 필요 없이 변경된 부분만 감지하여 빠르게 업데이트 가능

### `미림`

💬아직도 DOM보다 가상 DOM이 빠르다고 할 수 있는지는 모르겠음

DOM은 변경 사항을 업데이트하기 위해 DOM 전체 트리를 다시 렌더링하지만, 가상 DOM은 변경 사항이 있는 부분에 대해서만 업데이트를 수행합니다.

### `정욱`

실제 DOM 트리에 가해질 변경을 일괄적으로 적용하여 reflow/repaint가 발생하는 횟수를 줄이고, 이전 트리와 현재 트리 간 차이를 비교하여 변경을 최소화함으로써 실제 DOM을 더욱 빠르게 갱신하기 위해 활용될 수 있다.

### `영은`

디핑알고리즘을 통해 변경된 부분만 실제 DOM에 적용하는 방식으로 업데이트

## 5. 리액트의 렌더링은 어떻게 작동하나요 ? 이로 인해 잠재되었던 어떤 문제가 발생할 수 있나요 ?

### `보경`

- 상태나 props에 변경이 감지될 때마다 자식 컴포넌트를 리렌더링 한다.
- 자식요소가 정적인 경우에도 렌더링이 되는 문제가 있을 수 있어 적절한 메모이제이션이 필요

### `미림`

💬리액트의 “리렌더링” 동작 방식과 이 방식에 의한 문제를 묻는 질문인 듯

리액트는 최초에 렌더링을 하고, 상태 또는 프롭 변경 시 리렌더링이 트리거됩니다. 이 때 이전 가상 DOM과 현재 가상 DOM을 비교하는 디핑 작업을 수행하여 변경된 부분을 파악하는데, 디핑 알고리즘에 의해 부모 노드 변경 시 모든 자식 노드도 다시 렌더링되어야 하는 문제가 있습니다. `memo`, `useMemo` 등을 통해 이러한 문제를 해결할 수 있습니다.

### `정욱`

리액트는 컴포넌트 상태가 변경되면 해당 컴포넌트와 그 자손 컴포넌트를 재귀적으로 호출하며, 특정 컴포넌트가 어떤 상태에 종속되는지 알지 못하기 때문에 UI와 상태의 일관성을 위해 호출된 모든 컴포넌트를 다시 그리게 된다. 따라서 실제로 변경이 발생하지 않은 컴포넌트도 불필요하게 리렌더링하게 될 가능성이 있다.

### `영은`

- 부모 컴포넌트가 렌더링되면 자식 컴포넌트도 불필요한 렌더링될 수 있음
- 이를 방지하기 위해 `React.memo`, `useMemo`, `useCallback`을 활용 가능
