여기서부터 찐이군

- store는 `getState`, `setState`, `subscribe` 이 세 가지 메서드를 가짐.

```tsx
const createStore = <T extends unknown>(initialState: T): Store<T> => {
  let state = initialState;
  const callbacks = new Set<() => void>();

  const getState = () => state;

  const setState = (nextState: T | ((prev: T) => T)) => {
    state = typeof nextState === 'function' ? (nextState as (prev: T) => T)(state) : nextState;
    callbacks.forEach((cb) => cb());
  };

  const subscribe = (callback: () => void) => {
    callbacks.add(callback);
    return () => callbacks.delete(callback);
  };

  return { getState, setState, subscribe };
};
```

- callbacks: 구독자 목록 (Set이라 중복 없음)
- setState(): state를 변경하고, 모든 구독자 콜백 실행
- subscribe(): 구독 등록 및 해제 함수 반환

⇒ 상태가 바뀔 때마다 등록된 모든 구독자(callback)를 다시 실행시킴

(문득 store라는 네이밍이 직관적이라고 느낌)

### **05. 리액트 컨텍스트와 구독을 이용한 컴포넌트 상태 공유**

컨텍스트는 컴포넌트 트리 전체에 데이터를 공급하고, 구독은 변경 시점에 자동으로 리렌더링을 유도

⇒ 전역이 아니라, 특정 컴포넌트 트리 단위로 모듈 상태를 공유하는 store를 만드는 것

⇒ 근데 뭔말인지 잘 모르겠다

- 컨텍스트를 써야하는 순간이 언제인지 아는것이 중요하다.
