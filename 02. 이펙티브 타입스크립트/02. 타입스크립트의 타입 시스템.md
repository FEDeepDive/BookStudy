## 📌목표

- 타입 시스템이란 무엇인가
- 타입 시스템을 어떻게 사용해야 하는가
- 타입 시스템으로 무엇을 결정하고, 가급적 사용하지 말아야 할 기능은 무엇인가

## 📌타입은 집합

- 타입은 **할당 가능한 값들의 집합**(범위)
- 타입스크립트에서 타입은 상속 관계가 아니라 집합으로 표현됨
- ‘A를 B에 할당 가능하다’ == ‘A는 B의 부분 집합(sub type)이다’
- 타입과 집합 개념 연결하기
    
    
    | 타입 개념 | 집합 개념 | 예시 |
    | --- | --- | --- |
    | `never` | 공집합 | 무한 루프하는 함수의 반환값 |
    | 유닛 타입, 리터럴 타입 | 원소가 1개인 집합 | T1 = ‘a’ |
    | 유니온 타입 | 합집합 | T1 | T2 |
    | 인터섹션 타입 | 교집합 | T1 & T2 |
    | `unknown` | 전체 집합 |  |

### 인터섹션 타입과 교집합

- 타입스크립트에서 타입의 이해
    - 타입은 ‘실제 값’이 아니라 ‘값들의 집합’임
    - 아래 예시에서 `Person` 타입은 `name: string`을 **가진 모든 객체들의 집합**임
    - 즉 타입이 달라도 `name: string`을 갖는 객체는 `Person` 이라는 집합에 속함
        
        ```
        💡        
        단, 객체 리터럴을 직접 할당할 때에는 **잉여 속성 체크**(excess property checking, 초과 속성 검사)가 수행되어 오류가 날 수 있다. 하지만 이는 타입 시스템의 본질이 아니라 편의적인 검사이며, 기본적으로는 구조적 타이핑임을 인지하자.
        ```
        
- 인터섹션의 이해
    - `&` 연산자는 ‘값의 집합’을 기준으로 교집합을 구함
    - 속성끼리 비교해서 공통 속성(값)이 있는지 따지는 게 아님!
    - **A 집합에도 포함되고 B 집합에도 포함되는 집합**을 의미함
- 예시
    
    ```tsx
    interface Person {
      name: string;
    }
    interface LifeSpan {
      birth: Date;
      death?: Date;
    }
    type PersonSpan = Person & LifeSpan; // never 타입이 아니라 ...
    type PersonSpan = {
    	name: string;
    	birth: Date;
    	death?: Date;
    }
    ```
    

## 📌잉여 속성 체크(excess property checking)

- **객체 리터럴을 직접 할당할 때** 추가 속성을 허용하지 않음
    
    ```
    📢
    본질적으로 구조적 타이핑이므로 추가 속성이 있어도 할당 가능하나, 편의를 위해 검사함‼️
    ```
    
- 장점
    - 의도와 다르게 작성된 코드(ex. 속성명 오타)를 찾기 쉬움
    - 구조적 본질을 해치지 않으면서도 객체 리터럴에만 추가 속성을 허용하지 않음 ⇒ 안정성 확보
- 한계
    - 객체 리터럴에만 적용됨
    - 객체 리터럴이 아닌 객체 변수를 직접 할당하거나, 타입 단언을 통해 피할 수 있음
- 예시
    
    ```tsx
    interface T {
    	title: string;
    }
    
    // 오류
    const t1: T = { title: 'Title', darkMode: true };
    //                             ~~~~~~~~ 'T' 형식에서 'darkMode'를 찾을 수 없음
    
    // 정상
    const temp = { title: 'Title', darkMode: true };
    const t2: T = temp;                  // 임시 변수 할당
    const t3: T = document;              // 구조적 타이핑
    const t4 = { title: 'Title', darkMode: true } as T; // 타입 단언
    ```
    
- 주의할 점
    - 경우에 따라 적용된다는 점 때문에 혼동이 올 수 있음
    - 한계를 인지하고, **잉여 속성 체크와 일반적인 구조적 타입 체크가 별도의 과정임을 이해할 것**

## 📌타입 공간과 값 공간의 심벌

같은 이름이어도 문맥에 따라 타입으로 사용되거나 값으로 사용될 수 있다.

- 타입과 값 두 가지로 사용되는 키워드: `class`, `enum`
- 공간에 따라 다른 목적으로 사용되는 키워드
    
    
    |  | 값 공간 | 타입 공간 |
    | --- | --- | --- |
    | &, | | AND, OR 비트 연산자 | 인터섹션, 유니온 연산자 |
    | this | 자바스크립트의 this | 타입스크립트 다형성 this 타입 |
    | in | 루프 (`for .. in`) | 매핑된(mapped) 타입 |
    | const | 변수 선언 키워드 | 타입 단언 (`as const`) |
    | extends | 클래스 상속 | 타입 확장 |

## 📌타입 시스템에서 주의해야 할 기능

### 타입 단언보다 선언 사용하기

- 타입 선언(`: Type`): 할당되는 값이 해당 인터페이스를 만족하는지 검사함 ⇒ 결과에 따라 오류 표시
- 타입 단언(`as Type`): 추론한 타입이 있더라도 강제로 타입을 지정 ⇒ 오류가 있어도 무시
- 타입 단언이 타당한 경우
    - 추론된 타입보다 내가 판단한 타입이 더 정확할 때 (ex. DOM 요소 정보)

### 함수 표현식에 타입 적용하기

- 타입스크립트에서는 함수 선언문보다 함수 표현식을 사용하자
- ⇒ 매개변수나 반환 값 타입을 선언하는 것보다, 함수 전체의 타입을 선언하는 게 간결하고 안전함
- ⇒ 함수 시그니처가 동일할 때, 정의한 타입을 재사용할 수 있음!
- 다른 함수의 시그니처를 참조하려면 `typeof fn`을 사용하면 됨

### 객체 래퍼 타입 피하기

- 객체 래퍼 타입(`String`)과 기본형 타입(`string`)은 다름
- 기본형 타입으로 써도 내부적으로 필요에 따라 객체 타입을 래핑/언래핑하므로, 일반적으로 직접 사용할 필요가 없음
- 객체 래퍼 타입을 직접 사용하거나, 인스턴스를 생성하지 말고 기본형 타입을 사용하자

## 📌타입과 인터페이스 차이점

- 인터페이스끼리 복잡한 연산을 할 수 없음 (타입은 타입끼리 유니온 등 복잡한 타입 확장 가능)
- 인터페이스는 한 타입에 대한 여러 선언이 병합되므로, 보강이 가능함
- 프로젝트에서 인터페이스 혹은 타입 중에 한 가지를 일관되게 사용하는 걸 추천

```
❓
왜 인터페이스 선언부를 수정하지 않고 선언 병합을 이용할까?
⇒ 타입 정의와 사용하는 위치가 분리되어 있는 환경(ex. 외부 라이브러리 타입을 확장하고 싶을 때)에서 유용함
```

## 📌타입 연산과 제네릭으로 DRY원칙 준수하기

DRY 원칙은 타입에도 적용해야 한다. 중복을 제거하기 위해 `keyof`, `typeof`, 인덱싱, 매핑된 타입, 제네릭 타입(`Pick`, `Partial`, `ReturnType` 등)에 익숙해져야 한다.

- 타입을 정의하고 재사용하기
- 이미 있는 타입을 확장해 사용하기
- 타입스크립트 도구를 사용해 부분 타입 생성하기
    - 인덱싱
        
        ```tsx
        type SubState = {
        	userId: State['userId'];
        	title: State['title'];
        }
        ```
        
    - 매핑된 타입
        
        ```tsx
        type SubState = {
        	[k in 'userId' | 'title']: State[k]
        }
        ```
        
    - 제네릭 타입 `Pick`
        
        ```tsx
        type SubState = Pick<State, 'userId' | 'title'>;
        ```
        
- 모든 키를 optional로 만들어야 할 때, 타입스크립트 도구 사용하기
    
    ```tsx
    type Options = { ... };
    type OptionsUpdate = {[k in keyof Options]?: Options[k]}; // keyof 사용하는 방법
    type OptionsUpdate = Partial<Options>; // 제네릭 타입 Partial 사용하는 방법
    ```
    

## 📌읽기 전용 타입

- `readonly`(객체의 경우 `Readonly`)을 사용해 타입을 읽기 전용으로 만들 수 있음
- **만약 함수가 매개변수를 수정하지 않는다면 `readonly`로 선언하는 것이 좋음**
    - 원본을 해치지 않음을 보장할 수 있음 & 함수 매개변수에 사용해 더 넓은 타입으로 호출 가능
    - but 어떤 함수를 `readonly`로 만들면 해당 함수를 호출하는 함수도 `readonly`로 만들어야 함
- `const`는 재할당을 방지하고 `readonly`는 변경(mutation)을 방지하므로 서로 의도가 다름!
- 얕게 적용되므로, 깊게 적용하고 싶으면 `ts-essentials` 라이브러리의 `DeepReadonly`를 추천

## 📌인덱스 시그니처로 동적 데이터 표현하기

- 인덱스 시그니처는 객체에서 키-값 구조를 유연하게 표현하기 위해 사용함
    
    ```tsx
    interface StringArray {
      [index: number]: string; // 인덱스 시그니처
    }
    ```
    
- 주의할 점
    - 키는 키끼리, 값은 값끼리 같은 타입을 가져야 함
    - 타입만 맞다면 어떤 키-값이든 허용함
    - 특정 키가 필요하지 않으므로 빈 객체도 유효함
- ⇒ 객체의 키 이름이 미리 지정되지 않았거나 알 수 없는 **동적 데이터 표현에 유용함** (ex. API 응답, 설정 객체, 파일 등)
    
    ```
    💡
    동적 데이터가 예측 가능한 형태라면 타입 단언 + `undefined` 체크로 대체 가능
    ```
