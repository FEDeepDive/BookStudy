## 📌타입 추론의 효과

타입스크립트는 자동으로 타입을 추론함 ⇒ 개발자가 수동으로 명시해야 하는 타입 구문의 수를 줄임

단! 다음 경우 타입을 명시하자

- 객체 리터럴 정의 시
    - 오류 위치가 객체 선언부에 표시되도록 (안하면 사용하는 곳에서 오류남)
- 함수 반환 타입
    - 오류 위치가 함수 선언부에 표시되도록
    - 함수에 대한 정보 제공
    - 명명된 타입 사용을 위해

## 📌타입 넓히기

타입 체커는 변수에 할당된 하나의 값만 가지고 해당 변수가 가질 수 있는 값의 집합, 즉 타입을 유추함

⇒ 매우 많은 타입이 해당 변수의 타입으로써 유효할 수 있음

⇒ 타입 체커는 그 많은 타입 중에 무엇이 개발자가 원한 타입인지 모르며, 유연성과 명확성 사이의 균형을 유지하려고 함(=적당한 걸 선택할 뿐임)

⇒ 즉 **추론된 타입은 내 생각과 다를 수 있고, 이로 인해 오류가 발생할 수 있음**

⇒ 그러므로 **타입 체커가 타입을 잘 추론할 수 있도록 코드를 짜야 함**

- 값을 `const`로 선언해 리터럴 타입으로 좁히기
    
    ```tsx
    let a = 1; // a의 타입은 number
    const a = 1; // a의 타입은 1
    ```
    
- 객체는 `const`로 선언해도 내부 요소가 리터럴 타입으로 좁혀지지 않으므로…
    - 타입 직접 명시
    - 타입 체커에 추가적인 문맥 제공 (ex. 함수 매개변수로 값을 전달)
    - 타입 단언
        - 요소에 `as const` 사용 ⇒ 해당 요소가 리터럴 타입이 됨
        - 객체에 `as const` 사용 ⇒ 각 요소가 `readonly` + 리터럴 타입이 됨

## 📌타입 좁히기⭐

조건문으로 타입 분기하여 좁히는 여러 가지 방법

- `instanceof` (`x instanceof T`)
- 속성 체크 (`key in someObject`)
- 내장 함수 (`Array.isArray()`)
- 태그 명시 (속성에 타입을 명시하는 방법) (⇒태그된 유니온, 구별된 유니온)
- `typeof` (`typeof x === "string"`)
- 커스텀 타입 가드: 타입 식별을 돕기 위해 직접 함수를 만드는 방식
    
    ```tsx
    const people = ['a','b','c','d','e'];
    
    // 일반 메소드로 undefined를 없애려고 시도해도 잘 동작하지 않음
    // filter가 타입 좁힌다는 사실을 추론하지 못하기 때문임
    const bc = ['b', 'c'].map(
    	who => people.find(n => n === who) // (string | undefined)[]
    ).filter(who => who !== undefined); // (string | undefined)[] << 여기 !!!
    ```
    
    ✅타입스크립트 v5.5부터는 타입 좁히기 기능이 똑똑해져서 `string[]`으로 잘 인식함
    
    ```tsx
    // 커스텀 타입 가드를 사용
    function isDefined<T>(x: T | undefined): x is T {
    	return x !== undefined;
    }
    
    // undefined가 없어짐
    const bc = ['b', 'c'].map(
    	who => people.find(n => n === who) // (string | undefined)[]
    ).filter(isDefined); // string[]
    ```
    
    반면 커스텀 타입 가드를 사용하면 타입이 좁혀진다. 이는 시그니처의 `x is T`로 인해 이 함수가 `undefined`를 제거한다는 것을 타입스크립트가 정확히 이해하기 때문이다.
    
    - 타입 술어란?
        - `x is T`와 같은 구문
        - 함수 반환 타입에 쓰면 타입 가드 함수로 동작함

### 주의할 점

- nullish와 falsy는 다름! 값을 불리언으로 사용할 때 주의
- `typeof null`은 `'object'`임을 주의

## 📌객체 한꺼번에 생성하기

- 객체 생성 시 프로퍼티를 동적 삽입하지 말고 선언할 때 한 번에 선언하자.
    
    ```tsx
    // bad
    const point = {};
    point.x = 3; // '{}' 형식에 'x' 속성이 없습니다.
    point.y = 4; // '{}' 형식에 'y' 속성이 없습니다.
    
    // good
    const point = {
    	x: 3,
    	y: 4,
    };
    ```
    
- 작은 객체를 조합해서 큰 객체를 만들 때에는 spread 연산자를 사용하자.
    
    ```tsx
    const coordinateX = {x: 3};
    const coordinateY = {y: 4};
    const coordinates2D = {...coordinateX, ...coordinateY};
    ```
    
- 이때 optional 속성을 추가하려면 삼항 연산자를 사용하자.
    
    ```tsx
    const firstLast = {first: 'Harry', last: 'Truman'};
    const fullName = {...firstLast, ...(hasMiddle ? {middle: 'S'} : {})};
    ```
    
- 단, 한 조건에 여러 속성을 추가한다면 optional이 아닌 유니온 타입이 되므로 주의.
    
    ```tsx
    const nameTitle = {name: 'Khufu', title: 'Pharaoh'};
    const pharaoh = {
    	...nameTitle,
    	...(hasDates ? {start: -2589, end: -2566} : {})
    };
    
    // pharaoh의 타입 
    const pharaoh: {
    	start: number;
    	end: number;
    	name: string;
    	title: string;
    } | {
    	name: string;
    	title: string;
    };
    
    pharaoh.start; // '{	name: string;	title: string;}' 형식에 'start' 속성이 없습니다.
    ```
    
    `start`, `end`는 항상 함께 사용되므로 opional 속성보다 아예 분리된 유니온 타입이 더 정확하다.
    
    optional 속성으로 표현하려면 헬퍼 함수나 lodash 같은 라이브러리를 사용하면 된다.
    
## 📌문맥에서 타입이 어떻게 추론되는지 이해하기

- 타입을 추론할 때 값만 고려하는 게 아니라 문맥도 함께 고려함
- TS는 일반적으로 값이 처음 등장할 때(할당/선언될 때) 타입을 결정함
    
    ```tsx
    type Language = 'Javascript' | 'Typescript';
    function setLanguage(language: Language) { /*...*/ }
    
    setLanguage('Javascript'); // fine
    
    let js = 'Javascript'; // js의 타입은 string으로 결정됨!
    setLanguage(js); // 매개변수 타입은 Language. 서로 달라서 오류 발생
    ```
    
- 변수를 별도로 선언했을 때 오류가 발생한다면…
    
    ```tsx
    // const로 선언하기
    const js = 'Javascript';
    
    // 타입을 명시하기 
    let js: Language = 'Javascript';
    
    // 상수 단언하기
    let js = 'Javascript' as const;
    // 단! 상수 단언 시 정의한 곳이 아닌 사용처에서 오류가 발생하므로 주의
    ```
    
## 📌함수형 기법과 라이브러리로 타입 흐름 유지하기

- 내장된 함수형 메서드나 lodash 라이브러리 등을 사용하면, 타입 구문을 직접 명시할 필요성이 줄어듦!


## 💬느낀 점

- 타입스크립트의 타입 추론을 특별하게 생각한 적이 없었는데, 3장 첫 페이지에서 타입 추론의 효과들을 읽고 나니 좀 특별하게? 느껴졌다. 생각해보면 그동안 내가 접한 언어들은 (js, python 제외) 모두 타입을 명시해야 했는데, 타입 구문을 생략해도 되는 언어는 없었음… 불편하다는 생각은 안해봤지만, 타입스크립트가 왜 사랑받는지 조금 더 알게된 느낌이었다. 단순히 자바스크립트에 타입만 추가한 게 아니라, 유연하게 동작할 수 있는, 세심하게 설계된 녀석이구나 싶었음.
- 타입 추론이 잘 되게끔 코드를 쓰는 게 중요하겠다는 걸 깨달음 (+ 여기서 실력이나 내공의 차이가 드러나겠구나~)
- 타입 술어(`a is T`)에 대해 처음 알게 됨
- 책에서는 `filter`가 타입 좁히기 동작을 못한다고 했지만, 타입스크립트 v5.5에서 개선되어 타입 좁히기가 잘 동작함. 다만 v5.5 미만 버전을 사용할 수도 있으니 알아두면 좋겠다
- 일부 아이템들은 당연한 말을 하는 것처럼 보였는데, 무의식 중에 알고 있는 내용이더라도 의식적으로 이유나 근거를 조목조목 짚어보는 것이 머리에 확실하게 각인되는 것 같다. 여기에 정리하기에는 책에 나와 있는 내용을 복붙하게 될 것 같아서 구태여 정리하진 않았음.
- lodash 안써봤는데 편의성 면에서 매우 자주 등장해서 손을 좀 대보면 좋겠다는 생각이 듦.
