### 아이템 19. 추론 가능한 타입을 사용해 장황한 코드 방지하기

약간 아이템 제목처럼 타입추론을 최대한 활용하라는게 핵심

인상깊은 부분

```tsx
const axis1:string ='x'; // 타입은 string
const axis2 = 'y' // 타입은 "y"
```

의도치 않게 1은 타입이 넓어질 수 있겠네 아무래도 y가 더 정확하다 상기가 됐음

그리고 뭔가 명시적 타입구 문 때문에 실제로 하나 바꿨을때 이것저것 바꿔야 하는 일이 많았던거 같긴함

- 불필요하게 `: string`, `: number` 같은 걸 달지 말고,
- **추론에 맡겨서 더 좁은 타입, 더 정확한 타입**을 얻어라.
- 정말로 필요할 때만 명시적으로 타입을 쓰자.

### 아이템 20. 다른 타입에는 다른 변수 사용하기

- `let` 보다 `const` 를 권장하는 이유와 일맥 상통하는 듯
- 타입은 작은 범위로써라
- 비슷한 모양이라도 역할이 다르다면 명확하게 타입을 정의해라

**가려지는 변수(Shadowing)**

- 같은 스코프 안 혹은 중첩된 스코프에서 변수 이름을 재사용하면, 타입이 섞이거나 의도가 모호해질 수 있다.
- 특히 for문이나 콜백 내부에서 `id`, `value` 같은 변수를 덮어쓰면 타입 추론이 꼬이기 쉽다.

```tsx
let id = "abc"; // string

function doSomething() {
  let id = 123; // number, 바깥 id를 가린다
  console.log(id); // 123
}

console.log(id); // "abc"
```

- 타입스크립트가 잘 잡아주긴 하지만, **같은 이름의 다른 타입**은 읽는 사람에게 혼란을 준다.
    
    → 이름을 더 구체적으로 (`userId`, `elementId`, `requestId` 등) 지으면 타입 오류도 줄고 가독성도 좋아진다.

### 아이템 22. 타입 좁히기

- 타스는 유니온타입을 조건문을 통해 타입 좁히기를 할 수 있다.
- 실제로 플젝에서 사용하고 있다
    
    프로젝트에서 스트리밍 API 응답을 처리할 때
    
    자연스럽게 `data.type`에 따라 `switch-case`로 분기해서
    
    각 타입별 로직을 처리하고 있었다.
    
    그땐 단순히
    
    - `"dry_run_cost"` → 비용 보여주기
    - `"html_report"` → 다운로드 링크
    - `"thinking"` → 단순 메시지
        
        이런 식으로 UI를 나누기 위해서 그렇게 코드를 짰지
        
        **타입스크립트의 타입 좁히기 개념을 의식해서 한 건 아니었다**
        
- 내가 switch-case로 처리했던 게 사실 타입스크립트 관점에선 유니언 타입을 좁히는(타입 좁히기) 대표적인 패턴이었구나.” 를 깨닫게 됐다.
- 이 책을 읽음으로서 또 알게 모르게 지식이 머릿속에 쌓이고 있다 써먹어보자 제발~!

### 아이템 25.  비동기 코드에는 콜백 대신 async 함수 사용하기

콜백지옥은 타스관점에서도 안좋음 

비동기 작업 콜백은 보통 (err, result) 이렇게 에러랑 결과를 동시에 넘기는데

에러가 있으면 결과가 없고 에러가 없으면 결과가 나타나야 하는 배타적 관계임

그걸 타입으로 완벽히 표현하기 힘들어서

`Error | null`, `T | undefined` 같은 복잡한 타입으로 표현되고,

결국 코드에서 `if (err)` 같은 걸로 계속 좁혀줘야 한다.

콜백이 중첩되면 그때마다 타입 좁히기를 또 해야 해서

타입 추론이 점점 꼬이고 유지보수도 힘들어진다.

반대로 `async/await` 쓰면 무조건 `Promise<T>`를 반환하기 때문에 훨씬 명확하다.

타입스크립트도 `Promise<타입>`으로 타입을 딱 잡아주니까

중간에 뭘 더 확인할 필요 없이 바로 안전하게 쓸 수 있다.

결국 복잡한 비동기 코드에선 콜백보다 `async`를 쓰는 게 타입스크립트 입장에서도 훨씬 깔끔하고 안정적이다.

### 아이템 26. 타입 추론에 문맥이 어떻게 사용되는지 이해하기

타입스크립트에서 타입 추론은 값 자체만 보고 하는 게 아니고,

**그 값이 놓인 문맥(어디에 쓰였는지)에 따라 완전히 달라진다.**

리터럴을 함수에 바로 넣으면 `"JavaScript"` 같은 게 유니언 타입에 깔끔하게 맞는데,

그걸 변수로 빼서 `let language = 'JavaScript'` 이렇게 쓰면

타입스크립트는 그냥 `string`으로 추론해서 타입이 안 맞아버린다.

튜플도 마찬가지다.

`panTo([10, 20])`은 `[number, number]`로 추론되는데

`const loc = [10, 20]` 으로 뺐다가 넣으면 `number[]`로 추론돼서 오류난다.

결국 이 아이템에서 하고 싶은 말은,

> 타입스크립트 타입 추론은 문맥에 따라 다르게 작동하니까
> 
> 
> 문맥 바꿨다고 갑자기 타입 깨지는 걸 보고 당황하지 말고
> 
> **그렇게 애매하게 짜지 말고**
> 
> 타입스크립트가 헷갈리지 않게 처음부터 의도를 명확히 드러내서 코드를 짜라
>
