## 감상평

### `보경`

- 아이템 19
  - 타입을 알잘딱깔센으로 타입을 작성해라
  - 객체리터럴과 함수 반환의 경우 타입 명시를 하지 않으면 코드가 정의된 곳이 아닌 사용되는 곳에서 오류가 나서 오류 추적이 어려워짐
- 아이템 20
  - 즉 타입이 다른 값은 변수를 재사용 하지 말고 분리해라
- 아이템 21
  - 타입스크립트가 작성된 코드를 정적 분석하는 시점에 변수는 가능한 값들의 집합을 가지게 됨. 타입체커는 이 때 타입을 가능한 값들의 집합을 유추해야 하는데 이 과정을 타입 넓히기라고 함
- 아이템 26
  - 타입은 “할당”시점에 추론되므로 문맥상 할당 시점의 타입과 값을 사용하는 위치에서의 타입이 일치 하는지 확인해봐야 함
- 전체
  - 타입 추론에서 개발자가 놓칠법한 여러 사례를 보여줘서 좋았다.
  - 아이템 26의 내용이 타입추론에서는 제일 중요한 것 같음
  - C++ 코드 분석할때 함수의 타입이 따로있어서 너무 보기 힘들었는데 아이템 27을 읽으면서 가독성을 위해서 분리를 하는것이 좋다는 것을 깨닫게 해줬다.
  - 이번장을 읽으면서 더 중요한게 용어를 느낌으로 아는것보다 명확한 의미를 알고 있어야 된다고 생각한다.

### `미림`

- 타입스크립트의 타입 추론을 특별하게 생각한 적이 없었는데, 3장 첫 페이지에서 타입 추론의 효과들을 읽고 나니 좀 특별하게? 느껴졌다. 생각해보면 그동안 내가 접한 언어들은 (js, python 제외) 모두 타입을 명시해야 했는데, 타입 구문을 생략해도 되는 언어는 없었음… 불편하다는 생각은 안해봤지만, 타입스크립트가 왜 사랑받는지 조금 더 알게된 느낌이었다. 단순히 자바스크립트에 타입만 추가한 게 아니라, 유연하게 동작할 수 있는, 세심하게 설계된 녀석이구나 싶었음.
- 타입 추론이 잘 되게끔 코드를 쓰는 게 중요하겠다는 걸 깨달음 (+ 여기서 실력이나 내공의 차이가 드러나겠구나~)
- 타입 술어(`a is T`)에 대해 처음 알게 됨
- 책에서는 `filter`가 타입 좁히기 동작을 못한다고 했지만, 타입스크립트 v5.5에서 개선되어 타입 좁히기가 잘 동작함. 다만 v5.5 미만 버전을 사용할 수도 있으니 알아두면 좋겠다
- 일부 아이템들은 당연한 말을 하는 것처럼 보였는데, 무의식 중에 알고 있는 내용이더라도 의식적으로 이유나 근거를 조목조목 짚어보는 것이 머리에 확실하게 각인되는 것 같다. 여기에 정리하기에는 책에 나와 있는 내용을 복붙하게 될 것 같아서 구태여 정리하진 않았음.
- lodash 안써봤는데 편의성 면에서 매우 자주 등장해서 손을 좀 대보면 좋겠다는 생각이 듦.
